# 거래 목록 화면 높이 맞춤과 전체 너비 목록 설계

- 작성일: 2026-10-30
- 상태: 승인됨 (2026-10-30)
- 기준: main `f8e67a2`(UI 밀도 축소 PR #57 반영 뒤). 간격·글자·`--control-height` 토큰은 그 커밋 값을 따른다.

## 1. 목표

- 좁은 화면(≤820px, PWA)에서 거래 목록 화면이 창 높이에 정확히 맞는다. 화면 전체 스크롤이 생기지 않고 목록만 그 안에서 스크롤한다.
- 상단 검색부(제목·필터)와 목록 영역을 나눈다. 목록은 페이징 풋터까지 포함해 남은 높이를 채우고, 풋터는 하단 탭 바 바로 위에 붙는다.
- 목록을 카드 모양 대신 전체 너비로 보여준다.
- 페이징 풋터는 이동 버튼 왼쪽에 `{현재 페이지} / {전체 페이지}`만 표시한다.
- 제목과 겹치는 `거래 추가` 버튼 글자를 `+ 추가`로 줄인다.
- 좁은 화면 목록 항목은 일시를 금액 밑으로 옮기고, 대분류·소분류 뒤에 `|` 구분자를 두고 메모를 표시한다.

넓은 화면(>820px)은 이미 셸이 창 높이(`100dvh`)이고 목록이 안에서 스크롤하므로 높이 규칙은 바꾸지 않는다.

## 2. 지금 상태 (2026-10-30 측정, 375×812)

- 셸은 좁은 화면에서 페이지 스크롤이다. 목록은 `max-height: 60dvh`로만 잘려 페이지 스크롤과 목록 스크롤이 겹친다. 행이 많으면 풋터가 탭 바에 가린다.
- `.layout`은 좁은 화면에서 `flex-wrap: wrap`이라 목록 카드가 내용 높이만큼 늘어난다. 높이를 맞추려면 이 줄바꿈이 목록 높이를 정하지 않게 해야 한다.
- 필터는 [범위] / [월] / [검색] 세 줄(컨트롤 44px)이다.
- 풋터는 `1–6 / 6건` + [이전 페이지] `1 / 1` [다음 페이지]이고, 44px 버튼 때문에 두 줄(81px)로 접힌다.

## 3. 범위

- 높이 맞춤은 **거래 목록 화면에만** 적용한다. 홈·대시보드·업로드·그룹 등 다른 좁은 화면은 지금처럼 페이지 스크롤을 유지한다.
- 전체 너비 목록은 두 폭 모두 적용한다. 좁은 화면은 좌우 끝까지(엣지투엣지), 넓은 화면은 카드 테두리만 없애고 본문 폭을 채운다.
- 하지 않는 것: 다른 화면의 스크롤 모델 통일, 금액 색(`--amount-income`/`--amount-expense`)을 거래 목록에 적용, 페이지 크기(500행) 변경, 날짜별 묶음 머리.

## 4. 화면 구조

```
셸 (좁은 화면에서도 거래 목록일 때만 100dvh)
├─ 상단 바
└─ 본문 (거래 목록일 때 스크롤하지 않음, 아래 여백 = 탭 바 56px + 안전 영역)
   └─ 페이지 (flex column)
      ├─ 검색부 (flex: none)  제목·추가 버튼 / 필터
      └─ 목록 영역 (flex: 1, min-height: 0)
         ├─ 목록 스크롤 (flex: 1, overflow: auto)  ← 여기만 스크롤
         └─ 페이징 풋터 (flex: none)
```

### 4.1 셸 높이 맞춤 (좁은 화면, 거래 목록만)

- 거래 페이지 루트에 표시를 달고(`data-fit-viewport` 속성), `AppLayout.module.css`에서 `:has()`로 그 표시가 있을 때만 좁은 화면 셸을 넓은 화면과 같은 모양으로 바꾼다.
  - 셸 `height: 100dvh`(`100vh` 대체값 포함), 줄바꿈 없음.
  - 본문 `flex: 1; min-height: 0; overflow: hidden`.
  - 본문 아래 여백은 `.withTabBar`의 `+ var(--space-4)`를 빼고 탭 바 높이 + 안전 영역만 둔다. 풋터가 탭 바 바로 위에 붙는다.
- 표시는 AppLayout이 경로를 알 필요 없게 페이지가 단다. 셸은 "표시가 있으면 창 높이"라는 규칙만 가진다.

### 4.2 검색부

- 좁은 화면 필터 배치: 1줄 [월 선택(전체 폭)], 2줄 [범위 | 검색(남은 폭)]. 세 줄이 두 줄이 된다.
- 그룹 거래의 멤버 선택은 2줄에서 범위 다음에 오고, 폭이 모자라면 줄바꿈한다. 이 경우 세 줄이 될 수 있다.
- 순서는 필터 줄 전용 클래스로 정한다. 공용 `ui.row`에 자식 선택자를 걸지 않는다. `ui.row`는 풋터 버튼 묶음 등 다른 곳에도 쓰이므로 같이 바뀐다(시안에서 실제로 겹쳐 확인함).
- 검색부와 목록은 목록 영역 위쪽 1px 구분선(`--line`)으로 나눈다. 검색부에 별도 배경 띠는 두지 않는다.

### 4.3 목록 영역 (전체 너비)

- 좁은 화면: 목록 영역을 본문 좌우 여백만큼 밖으로 늘린다. 음수 여백은 본문 여백과 같은 식을 쓴다: `max(var(--space-4), env(safe-area-inset-left/right, 0px))`. 16px 같은 고정값은 쓰지 않는다. 둥근 모서리·좌우·아래 테두리를 없애고 위 구분선만 둔다. 행 글자(`CardList` 좌우 여백 `--space-4`)가 검색부 왼쪽 끝과 맞는다.
- 넓은 화면: 같은 방식으로 카드 테두리·둥근 모서리를 없애고 본문 좌우·아래 여백만큼 늘려 본문 폭을 채운다. 사이드바 상세 패널도 둥근 모서리 없이 오른쪽 끝에 붙이고 위·왼쪽 테두리만 둔다. 목록과 패널 사이는 패널 왼쪽 테두리로 구분한다.
- `.layout`의 좁은 화면 `flex-wrap: wrap`은 사이드바 패널을 연 채 창을 좁힌 경우를 위한 것이었다. 높이를 맞춘 화면에서는 줄바꿈하면 목록이 사라지고 패널이 탭 바 밑으로 잘리므로(구현 중 재현), 그 경우에는 세로 배치로 바꾼다: 목록이 남은 높이를 갖고, 패널은 위 테두리만 둔 채 내용만큼(최대 60%) 차지하며 각자 안에서 스크롤한다. 패널에는 `position: relative`를 둬서 안쪽 절대 위치 요소가 패널 스크롤 밖으로 새지 않게 한다.
- 안전 영역: 목록·패널 배경은 화면 끝까지 늘리되, 안쪽 여백에 `env(safe-area-inset-left/right)`를 더해 가로 모드 노치에서도 글자가 가리지 않게 한다. inset이 0이면 여백은 그대로다.
- `.listScroll`의 좁은 화면 `max-height: 60dvh`를 없앤다.

### 4.4 페이징 풋터

- 배치: 오른쪽 정렬된 한 묶음 `{현재} / {전체}` [‹] [›]. 왼쪽의 `1–500 / 501건` 표시는 화면에서 없앤다.
- 이동 버튼은 `MonthPicker`처럼 `ui.button` + 아이콘(`chevron-left`/`chevron-right`)이고, 정사각형 폭을 `var(--control-height)`로 둔다. 좁은 화면 44px, 넓은 화면 32px. 40px 고정인 `ui.iconButton`은 쓰지 않는다.
- 접근성: 버튼 이름은 `이전 페이지`/`다음 페이지`를 `aria-label`로 유지한다. `role="status"`는 `{현재} / {전체}` 표시에 두고, 화면에 보이지 않는 텍스트로 건수 범위(`1–500 / 501건`)를 함께 읽게 한다. 화면 표시는 숫자만이다.
- 두 폭 모두 같은 풋터를 쓴다. 시안 측정 높이는 좁은 화면 57px(한 줄)이다.

### 4.5 추가 버튼

- 화면 글자는 `+ 추가`(아이콘 `plus` + `추가`)다. 두 폭 모두 같다.
- 접근 이름은 `aria-label="거래 추가"`로 둔다. 보이는 글자 `추가`를 포함하므로 음성 입력("추가 누르기")도 맞고, 화면 낭독기는 무엇을 추가하는지 듣는다. 기존 테스트의 `{ name: '거래 추가' }` 조회도 그대로 맞다.
- 추가 창 제목(`거래 추가 (수동)`)과 오른쪽 패널 이름(`거래 추가`)은 바꾸지 않는다.

### 4.6 목록 항목 (좁은 화면 `CardList`)

```
[내용 · 숨김 배지]                         [금액]
[대분류 · 소분류 · 멤버 | 메모] [수정됨 배지]  [일시]
```

- 1줄은 지금과 같다: 왼쪽 내용(+숨김 배지), 오른쪽 금액.
- 2줄 왼쪽: 분류 정보 `대분류 · 소분류`(그룹 거래면 `· 멤버 닉네임`까지)를 `·`로 잇고, 메모는 그 뒤에 ` | ` 구분자로 붙인다. 예: `식비 · 점심 | 회사 앞 김밥`. 소분류가 비면 그 칸과 `·`를, 메모가 비면(null·빈 문자열·공백만) ` | 메모` 전체를 생략한다.
- `|`는 장식 구분자다. 흐린 색(`--ink-muted`)으로 두고 `aria-hidden`으로 감싸 화면 낭독기가 읽지 않게 한다. 낭독 순서는 분류 → 메모 그대로다.
- 수정됨 배지는 말줄임 대상 밖에 둬서 메모가 길어도 잘리지 않게 한다.
- 2줄 오른쪽: 일시(`MM-DD HH:mm`, 고정폭 숫자, 줄바꿈 없음). 금액과 오른쪽 끝을 맞춘다.
- 2줄 왼쪽 글자(분류 | 메모)는 한 줄로 두고 넘치면 말줄임(…)한다. 메모 전문은 상세 창에서 본다. 행 높이는 지금과 같은 52px이다(시안 측정).
- 넓은 화면 표는 이번에 바꾸지 않는다. 표의 열(일시·카테고리·내용·결제수단·금액)과 메모 열 추가 여부는 별도로 정한다.
- 검색 대상(내용·카테고리)에 메모를 더하지 않는다.

## 5. 유지하는 동작

- 상세·추가 창: 좁은 화면 하단 시트, 넓은 화면 모달/오른쪽 패널 전환, 열고 닫을 때 포커스 이동, 뒤로가기로 모달 닫기.
- 목록 키보드 탐색(GridList/표), 선택 행 강조, 페이지 바꿀 때 목록 스크롤 맨 위로.
- 표의 고정 머리(`position: sticky`)와 가로 스크롤.

## 6. 위험과 확인할 것

- iOS 홈 화면 PWA에서 검색창을 눌러 키보드가 올라올 때 `100dvh` 셸이 어떻게 보이는지 시뮬레이터로 확인한다. 자동화 브라우저 시안에서는 확인하지 못했다.
- 본문 대신 목록이 스크롤하므로 iOS 상태 바를 눌러 맨 위로 가는 동작은 거래 목록에서 작동하지 않는다. 다른 화면은 영향 없다.
- `:has()`는 iOS 15.4 이상에서 동작한다. 지원하지 않으면 지금처럼 페이지 스크롤로 남는다(기능 손실 없음).
- 하단 탭 바 높이 56px은 `BottomTabBar`와 `AppLayout` 두 곳에 값으로 있다. 이번에 토큰으로 묶지 않는다.

## 7. 검증

- 단위 테스트(`TransactionsPage.test.tsx`): 풋터가 `1 / 2`를 표시하고, `role="status"`가 건수 범위를 함께 읽는지, 이동 버튼 이름이 유지되는지. 기존 `1–500 / 501건` 단정은 새 표시에 맞게 바꾼다. 추가 버튼의 보이는 글자가 `추가`이고 이름이 `거래 추가`인지. 좁은 화면 항목 2줄에 `대분류 · 소분류 | 메모`(빈 칸과 구분자 생략)와 일시가 나뉘어 나오는지.
- 레이아웃은 jsdom에서 측정할 수 없으므로 `/verify` 스택에서 확인한다.
  - 375×812: `document.documentElement.scrollHeight === innerHeight`, 목록 스크롤 요소 `scrollHeight > clientHeight`(행이 많은 달), 풋터 아래 끝 = 탭 바 위 끝, 목록 좌우 끝 = 화면 좌우 끝.
  - 그룹 거래 + 멤버 선택 상태에서도 위와 같은지.
  - 1280×800: 문서 높이 = 창 높이, 목록 테두리 없음, 오른쪽 패널 열기/닫기.
  - 다른 좁은 화면(홈·대시보드)은 지금처럼 페이지 스크롤인지.
- `.claude/skills/verify/features/transactions.md` 검증 레시피(기능 지도)에 바뀐 풋터·높이 규칙을 반영한다.
