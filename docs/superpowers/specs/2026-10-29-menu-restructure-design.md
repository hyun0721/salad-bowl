## 1. 목표

- 홈은 "지난달 데이터가 올라왔는지"와 지난달 요약만 보여준다. 월별 등록 현황과 월 데이터 관리는 업로드 메뉴로 옮긴다.
- 대시보드를 대분류·소분류 × 분포·추이 네 화면으로 나눈다. 웹은 대분류·소분류 두 메뉴로 묶고, 모바일은 한 화면씩 보여준다.
- 메뉴가 2단이 되므로 화면 이동 규칙(주소, 뒤로가기, 포커스, 월 유지)을 정한다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 소분류 범위 | 전체 소분류를 한 화면에 보여준다. 대분류를 고르지 않는다(b안) |
| 합계·멤버별 | 수입·지출 버튼(누르면 멤버별 창)을 대시보드 모든 하위 화면 위에 공통으로 둔다(a안). main에서 멤버별 표가 창으로 바뀌었다 |
| 모바일 하위 메뉴 | [대분류 \| 소분류] + [분포 \| 추이] 2단 선택(a안) |
| 홈 미업로드 버튼 | 업로드 메뉴로 이동하면서 그 달 업로드 창을 바로 연다(a안) |
| 웹 하위 메뉴 | 사이드바 "그룹 대시보드" 아래에 대분류·소분류 두 항목. 각 화면은 분포와 추이를 위아래로 함께 보여준다 |
| 주소 | 웹과 모바일이 같은 주소를 쓴다. 폭에 따라 보여주는 방식만 다르다 |
| 범위 밖 | 업로드 하위 메뉴(추후 구체화), 수입 추이, 태블릿 전용 폭 기준 |

## 3. 주소와 화면

| 주소 | 넓은 화면(>820px) | 좁은 화면(≤820px) |
|---|---|---|
| `/` | 홈 | 홈 |
| `/upload` (`?month=YYYY-MM`) | 등록 현황 + 업로드 + 이력. `month`가 있으면 그 달 업로드 창을 연다 | 같음 |
| `/dashboard` | `/dashboard/major`로 바꾼다(replace) | `/dashboard/major/share`로 바꾼다(replace) |
| `/dashboard/:level` (`major` \| `minor`) | 분포 카드 + 추이 카드 | `/dashboard/:level/share`로 바꾼다(replace) |
| `/dashboard/:level/:view` (`share` \| `trend`) | `/dashboard/:level`과 같은 화면이고 `:view` 카드로 스크롤한다 | 그 화면 하나만 |
| 그 밖의 `level`·`view` | `/dashboard`와 같이 처리 | 같음 |

- 대시보드 월은 `?month=YYYY-MM`으로 주소에 둔다. 하위 화면을 바꿔도, 새로 고쳐도, 링크를 보내도 같은 달을 본다. 없거나 형식이 틀리면 지금처럼 `defaultYearMonth`(지난달)이다.
- 폭이 바뀌어도(회전, 창 크기) 주소는 그대로 유효하다. 위 표대로 보여주는 방식만 바뀐다.
- 거래 목록·그룹 관리는 바꾸지 않는다.

## 4. 홈

- 남기는 것: 제목 "내 가계부", "지난달 내 요약" 카드.
- 새로 두는 것: "지난달 업로드" 카드. `GET /me/coverage?year=<지난달의 연도>`에서 지난달 항목을 찾는다.
  - 있으면: "M월 데이터 등록됨 · N건".
  - 없으면: "M월 데이터가 아직 없습니다"와 링크 "업로드하기" → `/upload?month=YYYY-MM`.
  - 불러오는 중·실패는 다른 카드와 같은 문구와 "다시 시도"를 쓴다.
- 빼는 것: 연도 선택, 월별 등록 현황 달력, 월 데이터 관리 창, "최근 업로드" 카드. 업로드 화면에 이미 전체 이력이 있으므로 최근 업로드 요약은 옮기지 않고 없앤다.

## 5. 업로드

- 순서: "월별 등록 현황"(연도 화살표 포함) → "파일 올리기" → "업로드 이력".
- 등록 현황의 동작은 지금 홈과 같다. 미등록 월은 업로드 창, 등록된 월은 데이터 관리 창(다시 업로드·삭제)을 연다.
- `?month=`가 있으면 그 달의 업로드 창을 열고, 주소에서 `month`를 지운다(replace). 새로 고쳐도 창이 다시 열리지 않게 하기 위해서다. 그 달이 등록된 달이면 데이터 관리 창을 연다.
- 파일 이동: `home/CoverageCalendar`, `home/MonthDataDialog`, `home/useDeleteMonth`, `home/coverageApi`를 `imports/`로 옮긴다. 쿼리 키(`['coverage', year]`)는 그대로 둔다.

## 6. 대시보드

### 6.1 공통 영역 (모든 하위 화면 위)

- 제목 "그룹 대시보드", 월 선택(`MonthPicker`, 주소의 `month`와 연결), 그룹·기준 안내 문구.
- 수입·지출 버튼과 멤버별 창(`MemberTotalsDialog`). 지금 `DashboardPage`의 것을 그대로 쓴다.
- 그 아래에 하위 메뉴(6.3)와 하위 화면.

### 6.2 하위 화면

| 화면 | 내용 |
|---|---|
| 대분류 분포 | 지금의 `CategoryBreakdown`(도넛 + 목록 + 거래 창) |
| 대분류 추이 | 지금의 `CategoryTrend` |
| 소분류 분포 | `CategoryBreakdown`을 소분류 데이터로. 거래 창은 그 소분류 거래 |
| 소분류 추이 | `CategoryTrend`를 소분류 데이터로. 칩 이름은 "소분류 · 대분류" |

- main의 `SubcategoryTrends` 카드(대분류를 골라야 보이는 추이 표 + 분포 막대)는 소분류 두 화면으로 대체한다. 그 카드의 "대분류" 선택은 두 화면 위의 거르기로 남기되, 기본값은 "전체 대분류"다(2장 결정: 전체 소분류). 대분류를 고르면 그 대분류의 소분류만 보인다.
- main 카드의 전월 대비 증감 강조(빨강 ↑, 파랑 ↓)는 소분류 추이의 "표로 보기"에 그대로 둔다. 대분류 추이 표가 이미 같은 규칙을 쓴다(PR #43).

- 대분류와 소분류는 같은 컴포넌트에 `level`을 넘겨서 그린다. 문구("대분류 선택", "대분류별 추이" 등)만 바뀐다.
- 추이의 기간 선택과 고른 칩은 하위 화면마다 따로 둔다. 대분류 이름과 소분류 이름이 섞이지 않게 하기 위해서다.

### 6.3 하위 메뉴

- 넓은 화면: 사이드바 "그룹 대시보드" 아래에 들여 쓴 링크 "대분류", "소분류"(`/dashboard/major`, `/dashboard/minor`). "그룹 대시보드" 자체는 `/dashboard` 링크이고, 하위 주소에서도 활성으로 보인다.
- 좁은 화면: 공통 영역 아래에 `<nav aria-label="대시보드 메뉴">`. 그 안에 링크 묶음 두 줄을 둔다: [대분류 | 소분류], [분포 | 추이]. 생김새는 `SegmentedControl`과 같게 하되 라디오가 아니라 링크(`NavLink`, `aria-current`)다. 화면을 바꾸는 이동이기 때문이다.
- 하단 탭은 지금처럼 5개다. `/dashboard/*`에서 "대시보드" 탭이 활성이다(`end: false`, 이미 그렇다).

### 6.4 이동 규칙

- 하위 메뉴 사이 이동(대분류↔소분류, 분포↔추이)은 `replace`로 한다. 뒤로가기를 누르면 대시보드에 들어오기 전 화면으로 돌아간다. 하위 화면은 형제 관계이고, 홈 화면 앱(PWA)에는 브라우저 뒤로가기 버튼도 없다.
- 하위 메뉴를 바꿀 때 `month`를 유지한다(링크에 지금 `search`를 붙인다).
- 포커스: `AppLayout`의 `FocusHeadingOnRouteChange`는 주 메뉴가 바뀔 때만(경로 첫 마디가 바뀔 때만) 제목으로 포커스를 옮긴다. 하위 메뉴를 누르면 포커스가 그 링크에 남아야 한다.
- 페이지 제목(`usePageTitle`): "그룹 대시보드 · 대분류 분포"처럼 하위 화면을 붙인다. 넓은 화면은 "그룹 대시보드 · 대분류"다.
- 카테고리 거래 목록은 지금처럼 창(넓은 화면 대화상자, 좁은 화면 하단 시트)이다. 주소를 만들지 않는다.

## 7. 소분류 데이터

### 7.1 API

main에 이미 `GET /groups/{groupId}/summary/subcategories?month=`가 있다. `month`까지 6개월의 `[{ month, major, minor, expense }]`를 준다. 선별은 요약과 같고, 빈 소분류는 "미분류"다. 분포와 추이는 이 응답을 웹에서 합쳐서 그린다. 바꾸는 것은 둘뿐이다.

- `subcategories`에 선택 값 `from`을 더한다. 없으면 지금처럼 `month - 5`다. 추이의 기간 버튼(전월·3·6·12개월·직접 지정)을 쓰기 위해서다. 검증은 `summary/trend`와 같다(최대 12개월, `from > month`면 400).
- `GET /groups/{groupId}/summary/transactions?month=&category=&minor=`에 선택 값 `minor`를 더한다. 있으면 대분류와 소분류가 둘 다 맞는 거래만 준다.
- 집계 키는 이미 (월, 대분류, 소분류)다. 같은 소분류 이름이 다른 대분류에 있으면(예: "기타") 따로 센다.
- 분포는 응답의 `month`(기준 월) 행만, 추이는 전체 행을 쓴다. 한 번 받아 두 화면이 같이 쓴다(쿼리 키 `['summary', groupId, month, 'subcategories', from]`).
- 배포는 서버를 먼저 반영한 뒤 웹을 공개한다(소분류 초기 조회 분석 문서의 두 단계 배포).

### 7.2 화면 표시 (설계 판단, 확인 필요)

소분류는 전체를 보여주기로 했다. 그런데 한 달에 소분류가 20~40개 나올 수 있어서 도넛 조각과 추이 선이 너무 많아진다.

- 분포 도넛: 위에서 9개만 조각으로 그리고, 나머지는 "그 외 N개" 한 조각으로 합친다. 목록에는 전부 보여준다. "그 외" 조각을 누르면 목록의 10번째 줄로 스크롤한다.
- 목록 한 줄: "소분류" 굵게 + "대분류" 흐리게 + 금액 + 비율.
- 추이: 지금처럼 처음에는 기간 합계 상위 5개만 켠다. 칩은 전부 늘어놓는다.
- UI 식별자는 `"${major}\u0000${minor}"`다. 이름만으로는 서로 다른 대분류의 같은 소분류를 구분할 수 없기 때문이다.

## 8. 메뉴 정의

- `app/menu.ts`에 하위 항목을 더한다. 예: `{ to: '/dashboard', ..., children: [{ to: '/dashboard/major', label: '대분류' }, { to: '/dashboard/minor', label: '소분류' }] }`.
- 사이드바는 `children`을 들여 써서 그린다. 하단 탭은 `children`을 무시한다.
- 좁은 화면의 2단 하위 메뉴는 대시보드 화면 안에 있는 컴포넌트다. `menu.ts`에 넣지 않는다. 대시보드만 쓰기 때문이다.

## 9. 테스트와 검증

- 단위·화면 테스트(Vitest, MSW)
  - 홈 카드의 세 상태(등록됨, 미등록 링크 주소, 실패).
  - 업로드 `?month=` 처리: 창이 열리고 주소에서 `month`가 지워지는지.
  - 대시보드 주소 표(3장)를 넓은 폭과 좁은 폭 각각에서 확인.
  - 하위 메뉴 이동이 `replace`이고 `month`를 유지하는지.
  - 하위 메뉴를 눌렀을 때 포커스가 그 링크에 남는지.
  - 소분류 분포의 "그 외" 합치기, 같은 소분류 이름의 구분, "전체 대분류"와 대분류 거르기.
- 지금 `HomePage.test.tsx`의 등록 현황 테스트는 업로드 테스트로 옮긴다.
- API 테스트: `from`을 준 `subcategories`가 기본 6개월 응답과 겹치는 달에서 같은지, 12개월 초과·역순 400, `minor`를 준 거래 목록이 그 소분류만 주는지.
- 실제 앱 검증: `/verify`로 넓은 폭과 좁은 폭 각각에서 홈 → 업로드하기 → 업로드 창, 대시보드 하위 4화면 이동과 뒤로가기를 확인한다. 끝나면 `/maintain-verification-skill`로 기능 지도(navigation, home, upload, dashboard)를 고친다.

## 10. 작업 나누기 (계획 단위 제안)

1. 홈·업로드 이관 (웹만, 4·5장).
2. 소분류 API 보강 (`apps/api`, 7.1: `from`, `minor`).
3. 대시보드 주소·하위 메뉴·이동 규칙 (웹, 3·6·8장). 처음에는 대분류 두 화면만.
4. 소분류 두 화면 (웹, 6.2·7.2). 2와 3이 끝난 뒤 진행.

1, 2, 3은 서로 겹치는 파일이 없어서 따로 진행할 수 있다.
