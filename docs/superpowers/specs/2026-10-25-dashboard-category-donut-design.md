# 대시보드 대분류 지출 도넛차트 설계

- 작성일: 2026-10-25

- 관련 문서:

  - [Plan 07c 후속](../plans/2026-10-25-plan-07c-followups.md), [Plan 08 후속](../plans/2026-10-25-plan-08-followups.md)
  - [번들 크기 기록](../../ui-library-poc.md)

## 1. 목표

그룹 대시보드의 "카테고리별 지출"을 도넛차트로 보여주고, 조각을 고르면 그 대분류의 그 달 거래 목록을 모달(좁은 화면은 시트)로 보여준다.

## 2. 확정된 결정 (사용자)

| 항목 | 결정 |
|---|---|
| 차트 구현 | **직접 SVG.** 새 의존성 없음. |
| 조각 수 | 대분류를 **묶지 않고 전부 개별 조각**으로 그린다. |
| 지출 0 이하 | 환불이 더 큰 대분류 등 지출이 0 이하인 항목은 차트와 목록 모두에서 **표기하지 않는다**. |
| 거래 목록 출처 | **API에 필터를 둔다.** 합계가 도넛과 어긋나지 않게 규칙을 서버 한 곳에 둔다. |
| 스크린리더 중복 | **줄인다.** 목록 행이 접근 가능한 컨트롤이고 도넛은 시각·포인터용이다(6.4). |
| 지출 ≤0 으로 합이 어긋날 때 | 제안대로: 가운데 총지출은 `summary.expense`. |
| 대분류가 빈 거래 | **"미분류"로 표기한다**(5.3). |

## 3. 차트 구현 방식 비교 (실측)

`vite build`, 도넛 하나와 조각 클릭만 만든 엔트리, 최소화 후 gzip. React 19.2.8 + react-dom만 번들한 기준(57.4 kB) 대비 증가분이다. 격리된 임시 프로젝트에서 쟀고 저장소에는 설치하지 않았다.

| 후보 (버전) | gzip 증가분 | React 19 | 키보드·스크린리더 | 라이선스 | 최근 릴리스 |
|---|---|---|---|---|---|
| **직접 SVG** | **+0.4 kB** | 해당 없음 | 전부 직접 구현(통제 가능) | — | — |
| d3-shape 3.2.0 | +2.9 kB | 해당 없음 | 직접 구현 | ISC | 2022-12 (정체) |
| visx 4.0.0 (`shape`, `group`) | +3.9 kB | peer ^18 \|\| ^19 | 직접 구현(저수준 프리미티브) | MIT | 2026-06 |
| Chart.js 4.6.1 + react-chartjs-2 5.3.1 | +50.4 kB | peer 19 허용 | canvas라 ARIA·대체 콘텐츠를 직접 달아야 함(공식 문서) | MIT | 2026-10 |
| Nivo `pie` 0.99.0 | +70.2 kB | peer 19 허용 | SVG, 내장 지원은 제한적(추측) | MIT | 2025-05 |
| Recharts 3.10.1 | +80.5 kB | peer 19 허용 | `accessibilityLayer` 기본 켜짐이나, 조각 키보드 선택→모달은 별도 구현 필요(추측: 공식 문서 확인 범위 밖) | MIT | 2026-07 |
| ECharts 6.1.0 (`core`+`PieChart`+`SVGRenderer`) | +118.3 kB | 래퍼 없이 직접 마운트 | canvas/SVG, 접근성 옵션은 별도 | Apache-2.0 | 2026-05 |

- 이 기능은 도넛 하나와 클릭뿐이라 라이브러리가 주는 것(툴팁, 애니메이션, 축)을 쓰지 않는다. 키보드·접근 이름·색 이중 부호화는 어느 후보든 직접 해야 한다.
- 라이브러리를 쓰면 대시보드 청크만 늘어도 gzip 50~120 kB가 늘어 지금 가장 큰 청크(106 kB)와 맞먹는다. 직접 SVG는 +0.4 kB다.
- 다음 차트(추이 등)가 생기면 그때 라이브러리를 다시 평가한다. `common/DonutChart.tsx`는 이 한 가지 일만 한다.

## 4. 기존 결정과 달라지는 점

- [React Aria 설계](2026-10-22-react-aria-rollout-design.md) 6.1 "카테고리 `<meter>`는 그대로 둔다"를 **번복한다.** `<meter>` 막대 목록은 도넛과 같은 정보를 주는 "대분류·금액·비율 목록"으로 바뀐다(막대 제거).
- 같은 문서 8장 "대시보드 표 정렬은 범위 밖"은 **그대로 유지한다.** 모달 안 거래 표도 정렬 없이 서버 순서(최신순)로 둔다.
- 이 변경은 위 문서의 6.1과 8장에 각주로 적는다.

## 5. API

### 5.1 새 엔드포인트

`GET /api/groups/{groupId}/summary/transactions?month=YYYY-MM&category=<대분류>` → `TransactionView[]`

- 거래 항목 모양은 기존 `GET /groups/{id}/transactions`와 같다(`TransactionViews.toViews`, `editable` 계산 재사용). 웹 타입도 `TransactionView`를 그대로 쓴다.
- 기존 `/groups/{id}/transactions`에는 필터를 덧붙이지 않는다. 그 엔드포인트는 이체·숨김 외 통화·타입을 거르지 않는 "전체 보기"라서, 요약 규칙을 얹으면 의미가 섞인다.

### 5.2 규칙을 한 곳에 둔다

- `SummaryService`의 "요약에 들어가는 거래" 선별(공개한 멤버, 숨김 제외, KRW만, 이체 제외)을 메서드 하나로 뽑고, `monthly()`와 새 `categoryTransactions()`가 둘 다 쓴다.
- 새 메서드는 그 결과에서 `type == EXPENSE`이고 `displayCategory().major()`가 `category`와 같은 거래만 돌려준다(override 반영). 환불(양수 금액의 지출 타입)도 포함해야 합계가 도넛 조각과 같다.
- 정렬은 `findVisibleBetween`의 `occurredAt desc, id desc`를 따른다.
- 권한은 `access.requireMember`로 `monthly()`와 같다.
- 응답 합계(금액 부호 반전)가 `byCategory[category].expense`와 같다는 것을 테스트로 고정한다.

### 5.3 빈 대분류는 "미분류"

- `displayCategory().major()`가 비었거나 공백뿐이면 요약과 새 엔드포인트 모두 "미분류"로 본다. 판정 메서드를 하나 두고(`SummaryService` 안) 두 곳이 같이 쓴다.
- 새 엔드포인트의 `category=미분류`는 대분류가 빈 거래를 돌려준다. 실제로 "미분류"라는 이름의 대분류가 있으면 한데 합쳐진다(요약도 같은 키로 합치므로 합계는 일치한다).
- 웹은 이름을 그대로 쓴다(별도 처리 없음).
- 한글·`/`가 들어간 대분류 이름이 쿼리스트링으로 안전하게 오가는지 테스트한다(웹은 `URLSearchParams`).

## 6. 웹

### 6.1 구성

| 파일 | 역할 |
|---|---|
| `common/DonutChart.tsx` (+ `.module.css`, `.test.tsx`) | 순수 SVG 도넛. react-aria-components를 쓰지 않는다. |
| `dashboard/CategoryBreakdown.tsx` (+ css, test) | 카드 한 장: 도넛 + 대분류·금액·비율 목록 + 모달 열기 |
| `dashboard/CategoryTransactionsDialog.tsx` (+ test) | `DialogFrame` 모달/시트, 안에 `DataTable`/`CardList` |
| `dashboard/dashboardApi.ts` | `categoryTransactions(groupId, month, category)` 추가 |
| `styles/tokens.css` | 차트 팔레트 토큰 추가 |

`DashboardPage.tsx`의 `<meter>` 목록은 `CategoryBreakdown`으로 바꾼다. 제목 "카테고리별 지출"과 `region` 접근 이름은 유지한다(기존 테스트가 이 이름으로 찾는다).

### 6.2 도넛

- 데이터: `byCategory`에서 `expense > 0`인 것만. 서버가 지출 큰 순으로 준 순서를 그대로 쓴다(12시 방향에서 시계 방향).
- 각 조각의 비율은 보이는 조각 합계 대비다. 가운데 문구는 "총지출 ₩N"이며 N은 `summary.expense`다(위 "지출" 카드와 같은 숫자). 환불이 더 큰 대분류가 숨겨지면 보이는 조각 합과 N이 다를 수 있다(예상: 드묾). 이때는 조각 합이 아니라 `summary.expense`를 쓴다.
- 비율 표시: 정수 %, 1% 미만은 "1% 미만". 반올림 때문에 합이 100이 아닐 수 있다.
- 조각이 하나뿐이면 호 계산이 퇴화하므로 두 반원으로 그린다. 조각 사이는 2px 간격(카드 배경색 선)이다.
- 아주 작은 조각은 누르기 어렵다. 같은 동작을 하는 목록 행(44px 이상)이 항상 있어 터치는 그쪽으로도 가능하다.
- 지출이 있는 대분류가 없으면 도넛 대신 기존 "지출이 없습니다." 문구를 쓴다.

### 6.3 색과 대비

- 팔레트는 dataviz 스킬의 검증된 기본 8색을 쓴다. 이 저장소의 카드 배경(라이트 `#ffffff`, 다크 `#1e221f`)에 대해 `validate_palette.js`를 돌렸고, 두 모드 모두 하드 게이트를 통과했다.

  | 슬롯 | 라이트 | 다크 |
  |---|---|---|
  | 1 | `#2a78d6` | `#3987e5` |
  | 2 | `#eb6834` | `#d95926` |
  | 3 | `#1baf7a` | `#199e70` |
  | 4 | `#eda100` | `#c98500` |
  | 5 | `#e87ba4` | `#d55181` |
  | 6 | `#008300` | `#008300` |
  | 7 | `#6250d6` | `#9085e9` |
  | 8 | `#e34948` | `#e66767` |

  - 라이트의 인접 쌍 최악 색각이상 ΔE 9.1, 일반 시야 ΔE 19.6. 다크는 8.4와 19.3이다(목표 8 이상, 일반 시야 15 이상).
  - 라이트에서 슬롯 3·4·5는 배경 대비가 3:1 미만이다(검증기 WARN). 색만으로 전하지 않는다는 원칙에 따라 이름·금액·비율 목록을 항상 함께 보여 이를 보완한다.
- 토큰은 `--chart-1`~`--chart-8`로 `tokens.css`의 세 곳(라이트, `prefers-color-scheme: dark`, `[data-theme="dark"]`)에 추가한다. 브랜드 초록(`--brand`)은 차트에 쓰지 않는다. 의미가 "선택·강조"라서 슬롯과 섞이면 헷갈린다.
- **8개를 넘는 대분류**: 새 색을 만들지 않는다(스킬 규칙: 9번째 색은 만들지 않는다). 대신 **색 × 무늬**로 구분한다. 9~16번째는 같은 8색에 45° 빗금 무늬, 17~24번째는 135° 빗금을 얹는다(스킬이 허용하는 복합 부호화). 25번째부터는 24번째 스타일을 되풀이한다(예상: 실제 대분류 수는 이보다 적다).
- 색은 인접 조각만 구분하면 되고, 정체성은 이름 목록이 맡는다. 슬롯은 크기 순서가 아니라 목록 순서로 배정하되, 대분류가 늘거나 줄어도 다른 달과 색이 달라질 수 있다는 점을 알고 간다(대분류별 고정 색은 범위 밖).

### 6.4 접근성

스크린리더가 같은 정보를 두 번 듣지 않도록, **접근 가능한 컨트롤은 목록 행 하나로 두고 도넛은 시각·포인터용**으로 둔다.

- 대분류·금액·비율 목록(`ul`)은 항상 보인다(도넛 옆, 좁은 화면은 아래). 차트만으로 정보를 전하지 않는다.
- 목록 행은 조각 하나와 1:1이다. 행은 `button`이고, 접근 이름은 "식비 32% ₩120,000"이다. 키보드는 Tab으로 행을 옮기고 Enter/Space로 모달을 연다. 행이 곧 "조각을 키보드로 고르는" 수단이다(조각 수만큼 Tab을 눌러야 하지만 한 줄 목록이라 순서가 예측 가능하다).
- 도넛 `svg`는 `aria-hidden="true"`이고 조각은 초점을 받지 않는다. 마우스·터치로는 조각을 눌러도 같은 모달이 열린다.
- 행에 초점이나 호버가 오면 해당 조각이 강조된다(윤곽선). 반대로 조각 위 호버는 행을 강조한다. 이렇게 행과 조각이 연결됨을 시각으로 보인다.
- 가운데 "총지출 ₩N"은 행 목록 위 제목 근처에 같은 정보가 있어 `aria-hidden` 도넛 안에 둬도 정보를 잃지 않는다. 총지출은 위 "지출" 카드에도 있다.
- 색만으로 구분하지 않는다: 이름과 비율이 행마다 글자로 있고, 8개를 넘는 조각은 무늬로도 구분한다(6.3).
- 초점·강조 윤곽선은 `--ink` 2px로 두 모드에서 3:1 이상이 되게 한다.
- 터치 영역은 목록 행 44px 이상이다. 작은 조각을 못 눌러도 행으로 열 수 있다.
- 동작 줄이기: 애니메이션은 쓰지 않는다.
- 원래 요구(조각 자체의 키보드 선택, 조각의 접근 이름)는 "행이 조각을 대표한다"는 방식으로 충족한다. 조각 `svg` 요소 자체가 초점을 받지는 않는다.

### 6.5 모달·시트

- `DialogFrame`을 쓴다(820px 초과 가운데 모달, 이하 시트). 제목은 대분류 이름이고 닫기 버튼은 `headerAction`이다. 바깥 클릭으로 닫힌다(입력이 없는 보기용 대화상자).
- 열린 동안 폭이 바뀌어도 모양을 유지하는 `useNarrowWhileOpen`을 `DialogFrame`이 이미 쓴다.
- 본문:
  - 요약 한 줄: "N건 · 합계 ₩X"(합계는 도넛 조각 금액과 같아야 한다).
  - 넓은 화면: `DataTable`, 열은 일시, 멤버, 내용, 소분류, 결제수단, 금액(환불은 음수 표시). 정렬 없음.
  - 좁은 화면: `CardList`. 첫 줄 내용·금액, 둘째 줄 일시·소분류·멤버(거래 화면 카드와 같은 모양).
  - 행을 눌러도 아무 동작이 없다(상세·수정은 거래 화면에서). `onRowAction`은 받되 비워 둔다(`DataTable`의 필수 prop).
- 상태: 불러오는 중, 실패(`role="alert"` + 다시 시도), 빈 목록.
- 쿼리 키 `['summary-transactions', groupId, month, category]`. 월을 바꾸면 모달을 닫는다.
- 닫으면 포커스가 눌렀던 조각(또는 목록 행)으로 돌아온다(RAC가 맡는다. 테스트로 확인).

## 7. 범위 밖

- 호버 툴팁, 그리기·전환 애니메이션, 범례 필터링, 대분류별 고정 색
- 모달 안 거래 정렬·상세·수정
- 멤버별 필터, 다른 달과 비교
- 소분류(minor) 단위 차트
- 기타 묶음(상위 N + 기타)
