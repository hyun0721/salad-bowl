# 대분류 거래 창 목록 구성과 고정 머리 설계

- 작성일: 2026-10-30
- 상태: 승인됨 (2026-10-30, 사용자 요청 그대로)
- 기반: [거래 목록 화면 높이 맞춤 설계](2026-10-30-transactions-fit-layout-design.md)(PR #59)의 카드·표 구성. 이 작업은 그 브랜치 위에 쌓는다.

## 1. 목표

- 대시보드 대분류 도넛 차트를 눌러 여는 창(`CategoryTransactionsDialog`)의 목록을 거래 목록과 같은 구성으로 보여준다.
- 창 제목 줄과 `N건 · 합계 ₩ …` 줄, 표의 열 머리를 고정하고 목록만 스크롤한다.

## 2. 목록 구성 (거래 목록과 같게)

거래 목록의 표 열과 카드를 한 곳에서 정의해 두 화면이 같이 쓴다. 그룹 거래이므로 멤버를 늘 보인다(`showOwner`).

- 넓은 화면 표: 일시 · 멤버 · 카테고리(`대분류 · 소분류` + 수정됨 배지) · 내용(+ 숨김 배지) · 결제수단 · 금액. 일시·금액 열 머리로 정렬할 수 있다.
  - 지금 창의 `소분류` 열이 `카테고리` 열이 된다. 창 제목이 이미 대분류지만 요청대로 거래 목록과 같게 둔다.
- 좁은 화면 카드: 1줄 `내용(+숨김) … 금액`, 2줄 `대분류 · 소분류 · 멤버 | 메모` + 수정됨 배지 … 일시. 규칙(빈 칸 생략, `|`는 `aria-hidden`, 말줄임)은 거래 목록 설계 4.6을 따른다.
- 행을 눌러도 아무 일도 없다(지금과 같음). 페이징은 없다(지금과 같음).

## 3. 고정 머리

- `DialogFrame`에 선택 속성 `pinnedHeader`를 더한다. 켜면 모달/시트가 세로 flex가 되고 본문(`.content`)이 남은 높이(`min-height: 0`)를 받는다. 제목 줄은 줄어들지 않는다. 다른 창은 바뀌지 않는다.
- 대분류 창은 `pinnedHeader`를 켜고, 본문을 [요약 줄(고정)] + [목록 스크롤 영역]으로 나눈다. 목록 스크롤 영역만 `overflow: auto`다.
- 넓은 화면 표의 열 머리는 목록 스크롤 영역 안에서 `position: sticky; top: 0`으로 고정한다(거래 목록과 같은 규칙).
- 크기: 넓은 화면 본문 최대 높이는 지금처럼 `min(70vh, 680px)`. 좁은 화면 시트는 지금처럼 최대 `70dvh`이고, 그 안에서 제목·요약을 뺀 높이를 목록이 쓴다.

## 4. 검증

- 단위 테스트: 넓은 화면 표 열 머리(`카테고리`, `멤버` 포함), 좁은 화면 카드 2줄(`외식`이 아니라 `식비 · 외식 · 나`, 메모 구분자), 요약 줄이 목록 스크롤 영역 밖에 있는지, 기존 테스트(아이콘 버튼, 합계, 닫힘 중 내용 유지, 재시도, 빈 상태).
- `/verify`: 375×812와 1280×800에서 행이 많은 대분류를 열고, 목록을 끝까지 스크롤해도 제목·요약·열 머리가 같은 자리에 있는지 잰다.
- 웹 최종 검증: `apps/web`에서 `npm run typecheck && npm test && npm run lint && npm run build`.
