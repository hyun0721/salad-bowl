## 1. 개요와 목표

**목적 (확정, 2026-11-11):** 회원의 현재 지출(신용카드 / 체크카드 / 현금영수증) 현황을 파악해,
남은 기간 어떤 지출 구분으로 소비해야 소득공제상 이익이 가장 큰지 판단하도록 돕는다.
소득공제의 모든 항목이나 모든 출처의 자료를 취합하는 것은 목적이 아니다.

회원은 신용·체크 사용액을 카드사별로, 현금영수증 사용액을 따로 입력한다. 시스템은 해당 귀속연도 세법 기준으로
현재 소득공제액을 계산하고, 남은 기간 지출을 어느 결제수단으로 쓰는 것이 유리한지 비교·추천한다.

목표

- (주 목표) 남은 기간 예산을 결제수단별로 어떻게 나누면 연말 소득공제액이 가장 커지는지, 그 차이와 이유를 보여 준다.
- 현재 지출 현황을 결제수단×소비구분 단위로 보고, 최저사용금액(총급여의 25%) 달성 여부·소득공제액·한도까지 남은 여유를 확인한다.
- 관리자가 귀속연도별 세법 수치를 갱신하고, 각 연도의 분석이 어떤 세법 버전으로 계산됐는지 보여 준다.

대상

| 대상 | 설명 |
|---|---|
| 회원 | 근로소득이 있는 거주자 본인(일용근로자 제외). 그룹 가입 여부와 무관하다. |
| 서비스 관리자 | 연도별 세법 기준을 작성·적용하는 운영자. 그룹 관리자(그룹 ADMIN)와 다른 개념이다. |

## 2. 범위와 비범위

범위 (첫 출시)

- 선택한 귀속연도의 전체 값 관리. 회원 × 귀속연도마다 연도 기록이 하나이고, 값을 덮어써 갱신한다. 시점별 기록과 비교 기능은 두지 않는다.
- 개인 누계자료(신용·체크 자료, 현금영수증 자료)의 수동 등록·조회·수정·삭제. 현금영수증 자료는 삭제 없이 편집만 한다(D19).
- 소득공제액 계산과 소비구분·결제수단 비율 조회
- 남은 예산에 대한 결제수단 배분 비교와 추천
- 관리자의 연도별 세법 기준 관리

비범위

| 항목 | 상태 | 이유 |
|---|---|---|
| 그룹 단위 합산·공유 | 확정 (후속 고도화) | 사용자 확정사항 |

## 4. 요구사항

상태 열은 모두 확정이다. D-항목 결정으로 확정된 것은 "확정 (Dxx)"로 적었다. "제안"이던 요구사항은 2026-11-12에 모두 확정됐다(13장 16번).
TAX-68~76은 와이어프레임 검토 결정(D16~D26)으로 추가했다.

### 4.1 접근·권한

| ID | 요구사항 | 상태 |
|---|---|---|
| TAX-01 | 회원은 본인의 소득공제 자료(연도 기록·입력자료·금액·지출계획)를 개별로 등록한다. | 확정 |
| TAX-02 | 소득공제 자료는 소유 회원만 조회·수정·삭제한다. 다른 회원의 자료를 ID로 요청하면 존재 여부를 숨기고 404로 응답한다. | 확정 |
| TAX-03 | 소득공제 자료는 그룹 공개 설정·그룹 역할과 독립이다. 그룹 미가입·탈퇴·선택 그룹 변경이 접근을 막거나 자료를 공개하지 않는다. 서버 검사는 "요청자 = 소유자" 하나이며 그룹 접근 헬퍼(`GroupAccess`)를 쓰지 않는다. | 확정 |
| TAX-04 | 연도별 세법 기준은 서비스 관리자만 "연도별 세법 관리" 화면에서 작성·수정·적용한다. | 확정 (D01). 관리자 지정·해제는 화면 없이 운영자가 DB에서 직접 한다 |
| TAX-05 | 서비스 관리자는 그룹 ADMIN과 별개의 권한이다. 그룹 역할을 세법 관리 권한으로 쓰지 않는다. | 확정 |
| TAX-06 | 일반 회원이 세법 관리 API를 호출하면 403, 세법 관리 화면에 URL로 들어오면 권한 없음 화면을 보여 준다. 서버가 요청마다 관리자 여부를 확인한다. | 확정 (D01) |
| TAX-07 | 로그아웃·세션 만료 시 소득공제 조회 캐시가 지워진다. 총급여·금액·작성 중인 값을 localStorage 등 브라우저 저장소에 두지 않는다. | 확정 |

근거: 현재 권한 규칙은 "인증 여부"뿐이고 역할이 없다(`SecurityConfig.java:70-75`, `User.java:18-43`).
그룹을 만든 회원은 자동으로 그 그룹의 ADMIN이 되므로(`GroupService.java:32`), 그룹 ADMIN을 재사용하면 모든 회원이 세법을 고칠 수 있다.
`GroupAccess.canViewOwnedBy/canEditOwnedBy`는 공개 중인 그룹 멤버·그룹 ADMIN에게 접근을 열어 주므로 급여 자료에 쓰면 안 된다.
로그아웃 시 `queryClient.clear()`가 전체 캐시를 비운다(`ClearCacheOnSignOut.tsx:10-13`). 쿼리 키 머리말은 `tax`처럼 기존 그룹 범위 키(`summary`, `bans` 등)와 겹치지 않게 한다.

회원 — 첫 등록

1. "소득공제"를 누른다. 선택 연도에 연도 기록이 없으므로 입력자료가 열린다(D16). 귀속연도를 고르고 기본정보(예상 총급여·근로기간(·자녀등 수))를 입력한다.

## 7. 계산·추천 정책

### 7.1 소득공제액 산식 (확정, 2026-11-12)

아래는 8.1절의 법령 조사 결과를 식으로 옮긴 것이다. 구현 전에 조문과 한 번 더 대조한다.

입력: 총급여 S, 연도 합계표 12칸, 세법 버전의 수치.
체크카드 사용분은 법의 "직불카드등"(공제율 30%) 분류로 계산한다. 아래 "직불등"은 체크카드와 현금영수증을 묶은 계산용 이름이며 화면에는 쓰지 않는다.

1. 구분 합계를 만든다.
   - 전통 T = 전통시장 3칸 합, 대중 P = 대중교통 3칸 합
   - S ≤ 문화체육 기준이면: 문화 M = 문화체육 3칸 합, 직불등 B = 체크카드 일반 + 현금영수증 일반, 신용 A = 신용카드 일반
   - S > 문화체육 기준이면: M = 0, B = 체크카드와 현금영수증의 (일반 + 문화체육), A = 신용카드의 (일반 + 문화체육)
2. 최저사용금액 L = S × 25%. 전체(A+B+M+T+P)가 L 이하면 공제액은 0원이다.
3. 공제 가능 금액 = A×15% + (B+M)×30% + (T+P)×40% − 차감액
   - L ≤ A: 차감액 = L×15%
   - A < L ≤ A+B+M: 차감액 = A×15% + (L−A)×30%
   - 그보다 크면: 차감액 = A×15% + (B+M)×30% + (L−A−B−M)×40%
4. 기본한도 H를 귀속연도·급여구간·자녀등 수로 정한다.
5. 추가 인정액 = min(공제 가능 금액 − H, T×40% + P×40% + M×30%, 추가한도 상한). 공제 가능 금액이 H 이하면 0.
6. 소득공제액 = min(공제 가능 금액, H) + 추가 인정액

공제율·기준 비율·한도는 세법 버전의 값이다. 위 숫자는 2025·2026 귀속 값이다.

합성 예시 1 (2026 귀속, 총급여 4,000만원, 자녀등 없음)

| 구분 | 금액 |
|---|---|
| 신용 일반 A | 12,000,000 |
| 체크·현금영수증 일반 B | 3,000,000 |
| 문화체육 M | 500,000 |
| 전통시장 T / 대중교통 P | 1,000,000 / 500,000 |

L = 10,000,000 ≤ A이므로 차감액 = 1,500,000.
공제 가능 금액 = 1,800,000 + 1,050,000 + 600,000 − 1,500,000 = 1,950,000. 기본한도 300만원 이내이므로 소득공제액 1,950,000원.

합성 예시 2 (2026 귀속, 총급여 8,000만원, 자녀등 없음)

신용 일반 30,000,000 / 체크 일반 10,000,000 / 체크 문화체육 1,000,000 / 전통시장 2,000,000 / 대중교통 1,000,000.
총급여가 7천만원을 넘으므로 문화체육 100만원은 체크 일반으로 본다: A = 30,000,000, B = 11,000,000, M = 0.
L = 20,000,000 ≤ A, 차감액 = 3,000,000. 공제 가능 금액 = 4,500,000 + 3,300,000 + 1,200,000 − 3,000,000 = 6,000,000.
기본한도 2,500,000. 추가 인정액 = min(3,500,000, 1,200,000, 2,000,000) = 1,200,000. 소득공제액 3,700,000원.

### 7.2 추천 정책 (확정, 2026-11-12)

- 고정하는 것: 남은 예산 총액, 소비구분별 금액, 회원이 "결제수단 고정"으로 표시한 금액.
- 바꾸는 것: "바꿀 수 있는 금액"을 신용카드에 둘지, 체크카드·현금영수증에 둘지.
  체크카드와 현금영수증은 공제율이 같아 추천에서는 한 묶음으로 다룬다.
- 방법: (현재 누계 + 계획)을 7.1 계산기에 넣어 시나리오별 연말 예상 공제액을 구하고 비교한다. 별도 근사식(잔여한도 ÷ 공제율 등)을 쓰지 않는다.
- 보여 주는 시나리오: 현재 계획 / 공제액이 가장 큰 배분. 공제액이 같으면 현재 계획을 유지하고 "차이 없음"으로 표시한다.
- 현재 계획(비교 기준, D17): "바꿀 수 있는 금액"을 지금까지의 결제수단 비율대로 쓴다고 본다. 배분 규칙은 아래와 같다.
- 추천은 [계산하기]를 눌러 저장한 지출계획으로 계산한다. 입력 중에는 다시 계산하지 않는다(D18).
- 자료가 미완료이거나 세법 준비 중이면 현재 계획과 추천을 계산하지 않는다(D25).
- 이유 문구는 계산 결과에서 나온 사실만 쓴다. 예: "신용카드 사용액이 이미 최저사용금액을 넘어, 남은 일반 지출은 체크카드·현금영수증이 공제율 30%로 더 높습니다."
- 전통시장·대중교통은 결제수단과 무관하게 같은 공제율이므로 결제수단 추천 대상이 아니다. 문화체육은 총급여 7천만원 이하일 때 같다.
- 카드 포인트·할인·연회비·전월실적은 고려하지 않는다는 점을 가정에 적는다.
- "한도까지 필요한 소비액"은 "참고: 한도까지 남은 공제 여유"로 표현하고 소비를 늘리라는 문구를 쓰지 않는다.

현재 계획의 배분 규칙 (확정, D17)

1. 소비구분마다 따로 나눈다. 그 소비구분의 "바꿀 수 있는 금액" V를 연도 합계표에서 그 소비구분의 지금까지 입력액 비율(신용카드 : 체크카드 : 현금영수증)로 나눈다.
2. 그 소비구분의 입력액 합이 0원이면 연도 전체(연도 합계표 12칸)의 결제수단 비율로 나눈다.
3. 연도 전체 입력액도 0원이면 V 전부를 신용카드에 둔다.
4. 나눈 금액은 결제수단마다 원 미만을 버린다. 버려서 남는 원은 신용카드에 더한다. 따라서 세 금액의 합은 항상 V와 같다.
5. 현재 계획의 결제수단별 금액 = 회원이 입력한 결제수단 고정액 + 위에서 나눈 금액. 체크카드 몫과 현금영수증 몫은 공제율이 같아 계산에서는 한 묶음이다.
6. 화면에 "현재 계획: 지금까지의 결제수단 비율(신용 n% · 체크 n% · 현금 n%)"를 적는다.

이 규칙의 원 미만 버림은 계획 금액을 원 단위 정수로 나누는 규칙이다. 소득공제액의 원 단위 처리(TAX-45)와는 별개다.

합성 예시 3 — 소비구분에 입력액이 있을 때 (규칙 1, 4)

일반 소비구분의 지금까지 입력액: 신용카드 3,000,000 / 체크카드 1,000,000 / 현금영수증 0. 합 4,000,000. 바꿀 수 있는 금액 V = 1,000,001.

| 결제수단 | 비율 | V × 비율 | 원 미만 버림 | 남는 원 | 현재 계획 배분 |
|---|---|---|---|---|---|
| 신용카드 | 3,000,000 ÷ 4,000,000 = 75% | 750,000.75 | 750,000 | +1 | 750,001 |
| 체크카드 | 1,000,000 ÷ 4,000,000 = 25% | 250,000.25 | 250,000 | | 250,000 |
| 현금영수증 | 0% | 0 | 0 | | 0 |

버린 뒤 합 = 750,000 + 250,000 + 0 = 1,000,000. 남는 원 = 1,000,001 − 1,000,000 = 1. 신용카드에 더해 750,001 + 250,000 + 0 = 1,000,001 = V.

합성 예시 4 — 소비구분의 입력액이 0원일 때 (규칙 2, 4)

문화체육 소비구분의 지금까지 입력액은 세 결제수단 모두 0원이다. 연도 전체 입력액: 신용카드 6,000,000 / 체크카드 3,000,000 / 현금영수증 1,000,000. 합 10,000,000. 문화체육의 바꿀 수 있는 금액 V = 333,333.

| 결제수단 | 연도 전체 비율 | V × 비율 | 원 미만 버림 | 남는 원 | 현재 계획 배분 |
|---|---|---|---|---|---|
| 신용카드 | 60% | 199,999.8 | 199,999 | +2 | 200,001 |
| 체크카드 | 30% | 99,999.9 | 99,999 | | 99,999 |
| 현금영수증 | 10% | 33,333.3 | 33,333 | | 33,333 |

버린 뒤 합 = 199,999 + 99,999 + 33,333 = 333,331. 남는 원 = 2. 신용카드에 더해 200,001 + 99,999 + 33,333 = 333,333 = V.

합성 예시 5 — 연도 전체 입력액이 0원일 때 (규칙 3)

연도 합계표 12칸이 모두 0원이고 일반의 바꿀 수 있는 금액 V = 500,000이면 현재 계획은 신용카드 500,000 / 체크카드 0 / 현금영수증 0이다.

### 8.3 버전 운영 규칙 (확정, D04·D21)

- 상태는 초안 → 적용이다. 적용본은 고칠 수 없고 삭제할 수 없다. 바꾸려면 새 초안을 만들어 적용한다(D04).
- 초안은 귀속연도마다 여러 개 둘 수 있다. 초안이 있어도 새 초안을 만들 수 있다(D21).
- 초안은 확인 한 번 뒤 삭제할 수 있다. 삭제한 초안은 복구되지 않고 기록도 남지 않는다(별도 감사 로그 없음, D13).
- 버전 번호는 귀속연도 안에서 초안을 만들 때마다 증가한다. 삭제한 번호를 다시 쓰지 않으므로 번호가 건너뛸 수 있다.
- 한 초안을 적용해도 다른 초안은 초안으로 남는다.
- 귀속연도의 현재 적용 버전은 하나다. 번호가 낮은 초안을 나중에 적용할 수 있으므로, 현재 적용 버전은 번호가 아니라 가장 최근에 적용한 버전으로 본다. **임시 해석이다(13장 18번).**

## 10. 상태: 오류·미완료·삭제·재계산

| 상태 | 조건 | 화면 동작 |
|---|---|---|
| 연도 기록 없음 | 선택한 귀속연도에 회원의 기록이 없다 | "소득공제"를 누르면 입력자료가 열린다(D16). 입력자료: 빈 상태와 기본정보 입력 안내. 분석·지출계획: 입력자료로 가는 안내 |

| 합계 0원 | 모든 칸이 0 | 빈 차트. 공제액 0원 |
| 최저사용금액 미달 | 전체 ≤ 최저사용금액 | 공제액 0원, 달성까지 남은 금액 표시(소비 권유 문구 없이) |

| 세법 준비 중 | 귀속연도에 적용 버전이 없다 | 자료 저장은 가능, 분석은 계산하지 않음. ② 지출계획 입력은 열려 있고 [계산하기]는 저장만 한다. ③ 자리에 "세법 준비 중"을 보인다(D25) |
| 새 세법 버전 있음 | 연도 기록의 버전보다 새 적용 버전이 있다 | 알림과 "새 버전으로 다시 계산". 누르기 전에는 기존 버전 결과 유지 |
| 근로기간 확인 필요 | 근로기간이 1~12월 전체가 아니다 | 결과에 주의 표시. 회원이 근로기간 사용분만 입력하도록 안내한다(D03. 합산 기간 기준은 미확인, 임시 규칙) |

| 없는 자료 | 없는 ID 또는 타인 자료 | 찾을 수 없음(404). 그룹 목록을 다시 불러오지 않는다 |
| 통신 오류 | 조회·저장 실패 | 오류 문구와 다시 시도. 입력한 값은 화면에 유지 |
| 삭제 | 신용·체크 자료 또는 연도 기록 삭제 | 확인 창에 함께 지워지는 범위를 적는다. 신용·체크 자료는 확인 한 번, 연도 기록은 귀속연도를 직접 입력해야 [삭제]가 켜진다(D22). 복구 불가(D05). 현금영수증 자료에는 삭제가 없다(D19) |
| 세법 초안 삭제 | 관리자가 초안을 삭제 | 확인 한 번 뒤 삭제, 복구 불가. 적용본에는 삭제가 없다(D21) |

창은 좁은 화면을 포함한 모든 폭에서 가운데 창(Dialog)으로 연다(D26).
