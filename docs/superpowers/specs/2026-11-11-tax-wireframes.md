# 소득공제 와이어프레임 설명서 — 검토본

작성일: 2026-11-11 (KST)
상태: **검토본. 사용자 확인 전.**
기준 문서: [소득공제 PRD](2026-11-11-tax-prd.md) (상태 줄 "사용자 결정 반영 완료, 제안 요구사항 확정 여부·탭 라벨 제외")
화면 산출물: [2026-11-11-tax-wireframes.html](2026-11-11-tax-wireframes.html) — 브라우저로 바로 연다. 외부 리소스·빌드 없음.

## 읽는 법

- HTML 위쪽 검토 컨트롤에서 **화면 / 폭(375px·데스크톱) / 보기(회원·관리자) / 상태**를 고른다. 모두 기본 폼 컨트롤이라 키보드로 조작한다.
- 상태를 고르면 그 상태가 보이는 화면으로 옮겨 간다. 화면을 바꿨을 때 그 화면에 없는 상태면 "기본"으로 돌아간다.
- `TAX-nn` 실선 표는 확정 요구사항, `TAX-nn 제안` 점선 표와 점선 영역은 **사용자 승인 전(PRD 13장 16번 질문)** 이다. 확정처럼 읽지 않는다.
- 회색 점선 "주석" 상자는 가정·열린 질문·그리지 않은 것을 적은 것이다.
- 저충실도다. 회색조·시스템 글꼴·단순 테두리만 썼고 앱의 디자인 토큰·부품 스타일은 가져오지 않았다. 용어와 배치만 현재 앱을 따랐다.
- 금액은 모두 합성값이다(총급여 50,000,000원, A카드·B카드). 세법 수치는 PRD 8.1절의 공개 법령 값이다.

## 화면

### A. 공통 셸 · 메뉴

- 목적: 메뉴 개편 결과와 역할별 노출을 확인하고, 좁은 화면 탭 라벨을 정한다.
- 영역
  - 데스크톱 사이드바: 홈 | 소득공제[입력자료 / 분석·지출계획 / 연도별 세법 관리(관리자만)] | 대시보드[대분류 / 소분류] | 거래 목록 | 그룹 관리. "업로드" 없음.
  - 375px 하단 탭 5칸: 홈·소득공제·대시보드·거래·그룹.
  - 소득공제 화면 안 탭: 375px에서만. 회원 2개, 관리자 3개. 데스크톱은 사이드바 2단 메뉴로 이동한다.
  - 헤더: 기존과 같다(그룹 선택). 소득공제 화면 머리에 "개인 자료 · 그룹과 무관" 표시.
  - 탭 라벨 비교: 안 1 "연도별 세법 관리" / 안 2 "세법 관리"를 본문 폭 343px로 나란히(375px에서는 위아래로) 보여 주고 줄 수를 잰다.
- 대시보드·거래·그룹 메뉴는 범위 밖이라 눌리지 않는다.

### B. 홈 (개편)

- 목적: 업로드 메뉴가 없어진 뒤 홈에서 등록 현황·업로드·이력을 모두 처리하는지 확인한다.
- 영역
  - 월별 등록 현황: 머리에 연도 이동(◀ 2026년 ▶)과 그 오른쪽 업로드 이력 아이콘 버튼. 월 칸 12개(등록됨 / 미등록 · 업로드하기 / 예정).
  - 지난달 내 요약 카드: 기존 그대로(수입·지출).
  - 없앤 것: "지난달 업로드" 카드, "파일 올리기" 카드.
- 창: 업로드 이력(기존 목록과 같은 항목), 미등록 월 → 업로드 창, 등록 월 → 데이터 관리 창. 뒤의 둘은 기존과 같아 제목·라벨만 그렸다.
- 데스크톱은 현황(넓게) | 요약 2단, 375px는 현황 → 요약 순으로 쌓는다.

### C. 소득공제 › 입력자료

- 목적: 귀속연도 하나의 기본정보와 누계자료를 넣고 합계를 확인한다.
- 영역(위에서 아래)
  1. 귀속연도 선택(올해·전년도·다음 해), 개인 자료 표시
  2. 기본정보: 예상 총급여·근로기간·자녀등 수, [수정]
  3. 신용·체크 자료: 카드사별 목록(기준일·합계·메모·완료/미완료), [신용·체크 자료 추가], 건별 [편집] [삭제]
  4. 현금영수증 자료: 연도 1건, [편집]. 입력 전에는 "미완료 · 4칸 빔"과 [4칸 0원으로 채우기]
  5. 연도 합계표(결제수단 3 × 소비구분 4)와 경고(미입력·기준일 불일치)
  6. 연도 기록 삭제
- 데스크톱은 왼쪽(2~4) | 오른쪽(5) 2단, 375px는 번호 순서대로 쌓는다.
- 창
  - 기본정보 수정: 총급여, 근로기간(시작월~종료월), 자녀등 수와 요건 3가지 안내
  - 카드사 자료 편집: 카드사명·기준일·메모, 8칸 표, [빈 칸 0원으로 채우기]
  - 현금영수증 자료 편집: 기준일·메모, 4칸
  - 자료 삭제 확인, 연도 기록 삭제 확인(함께 지워지는 범위 명시)
- 375px 배치(AC-23)
  - 8칸 입력: 행 = 소비구분 4, 열 = 신용카드 / 체크카드. 입력 2열이라 가로 스크롤이 없다.
  - 4칸 입력: 행 = 소비구분 4, 열 1개.
  - 연도 합계표: 행 = 소비구분 4 + 합계, 열 = 신용카드 / 체크카드 / 현금영수증. 행 합계 열은 없애고 소비구분 이름 아래 "계 n"으로 옮겼다. 데스크톱은 합계 열을 둔다.

### D. 소득공제 › 분석·지출계획 (방향 2개)

- 목적(주 목적): 현재 지출 현황을 보고, 남은 기간 어느 결제수단으로 쓰면 소득공제액이 커지는지 판단한다.
- 두 방향은 **같은 내용**(같은 영역·같은 숫자)을 다르게 배치한다. HTML에서도 한 벌의 내용을 배치만 바꿔 보여 준다.
- 공통 내용
  - 귀속연도 선택, 개인 자료 표시
  - 적용 세법(귀속연도·버전·적용일)·자료 기준일·예상 총급여 한 줄
  - 현재 요약 4칸: 현재 소득공제액(환급액 아님) / 최저사용금액 달성 / 기본한도 사용 / 추가한도 사용
  - ① 현황: 소비구분별·결제수단별 사용 비율(분모 = 전체 입력 공제대상액을 문장으로 명시), 공제액이 나온 과정, 참고(한도까지 남은 공제 여유)
  - ② 남은 기간 지출계획: 소비구분 4행 × (신용카드 고정 / 체크카드·현금영수증 고정 / 바꿀 수 있음), 합계 자동
  - ③ 추천 결과: 현재 계획 vs 추천 배분, 연말 예상 소득공제액과 차이, 이유, 가정. "차이 없음" 상태
  - 소비를 늘리라는 문구는 없다. 한도 관련 숫자는 "참고: 남은 공제 여유"로만 적었다.

| | 방향 1 · 한 화면 개요형 | 방향 2 · 단계형 |
|---|---|---|
| 구조 | 요약 4칸 → 추천 한 줄(결론) → 현황 \| 지출계획·추천을 한 화면에 모두 편다 | ① 현황 → ② 지출계획 → ③ 추천을 한 번에 한 단계만 본다. 단계 버튼과 이전/다음 |
| 결론 위치 | 맨 위 요약 아래 한 줄 + 아래 상세 | 마지막 단계 |
| 데스크톱 | 2단. 계획을 고치면 바로 아래 추천이 보인다 | 1단. 화면이 비어 보일 수 있다 |
| 375px | 한 줄로 길게 쌓인다(스크롤이 길다) | 한 화면에 한 가지 일 |
| 얻는 것 | 한눈에 보기, 현황과 추천 동시 비교, 다시 왔을 때 바로 결론 | 처음 쓰는 사람이 순서를 따라가기 쉽다, 입력에 집중 |
| 잃는 것 | 좁은 화면에서 입력표와 추천이 멀다 | 현황과 추천을 함께 못 본다, 다시 올 때마다 누름이 늘어난다 |

- 375px에서 지출계획 표는 소비구분별 묶음(라벨 + 입력 3줄 + 합계)으로 쌓는다.

### E. 소득공제 › 연도별 세법 관리 (관리자)

- 목적: 관리자가 귀속연도별 세법 수치를 초안으로 만들고 검증해 적용한다.
- 영역
  - 귀속연도 목록: 2027(적용 버전 없음) / 2026(적용 v1 · 초안 v2) / 2025(등록 안 함)
  - 버전 목록: v2 초안, v1 적용. 작성자·적용자·시각 표시. [직전 버전 복사해 초안 만들기]
  - 버전 상세: 최저사용금액 비율, 급여구간 경계 금액, 공제율 5종, 기본한도(급여구간 2 × 자녀등 0/1/2명 이상), 추가한도 상한(구간별), 계산 알고리즘 버전(고정), 근거(법령명·조문·URL)·적용 대상 기간·메모
  - 초안: [초안 저장] [검증] [적용]. 적용은 확인 창을 거친다.
  - 적용본: 모든 입력이 꺼진 읽기 전용, [이 버전을 복사해 새 초안 만들기]
- 데스크톱은 목록(1) | 상세(2) 2단, 375px는 연도 → 버전 → 상세 순으로 쌓는다.
- 회원 보기로 열면 "권한 없음" 화면이 나온다.
- 동작하는 것: v1/v2 전환, 검증 버튼, 적용 확인 창. 연도 전환과 초안 만들기는 그리지 않았다(2026년만).

## 열린 질문

3. 지출계획은 [저장] 버튼으로 저장하는가, 입력 즉시 추천을 다시 계산하는가. 버튼으로 그렸다.

6. 세법 초안이 있을 때 초안을 또 만들 수 있는가, 초안 삭제가 있는가. PRD에 없어 그리지 않았다.
