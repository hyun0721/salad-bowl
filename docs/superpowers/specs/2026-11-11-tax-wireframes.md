# 소득공제 와이어프레임 설명서 — 검토본

작성일: 2026-11-11 (KST) · 고친 날: 2026-11-12
상태: **검토본. 2026-11-12 사용자 결정(D16~D26, "제안" 확정) 반영.** 아래 "열린 질문" 3개가 남았다.
기준 문서: [소득공제 PRD](2026-11-11-tax-prd.md). D16~D26 번호는 2026-11-12 결정을 PRD에 옮길 때 쓰는 번호다.
화면 산출물: [2026-11-11-tax-wireframes.html](2026-11-11-tax-wireframes.html) — 브라우저로 바로 연다. 외부 리소스·빌드 없음.

## 읽는 법

- HTML 위쪽 검토 컨트롤에서 **화면 / 폭(375px·데스크톱) / 보기(회원·관리자) / 상태**를 고른다. 모두 기본 폼 컨트롤이라 키보드로 조작한다.
- 상태를 고르면 그 상태가 보이는 화면으로 옮겨 간다. 화면을 바꿨을 때 그 화면에 없는 상태면 "기본"으로 돌아간다.
- `TAX-nn` 표는 요구사항이다. "제안"이던 요구사항과 7.1·7.2 정책은 2026-11-12에 모두 확정돼 점선 구분을 없앴다.
- 회색 점선 "주석" 상자는 가정·열린 질문·그리지 않은 것을 적은 것이다.
- 저충실도다. 회색조·시스템 글꼴·단순 테두리만 썼고 앱의 디자인 토큰·부품 스타일은 가져오지 않았다. 용어와 배치만 현재 앱을 따랐다.
- 금액은 모두 합성값이다(총급여 50,000,000원, A카드·B카드). 세법 수치는 PRD 8.1절의 공개 법령 값이다.

- 2026-11-14부터 배치·글자 크기·도움말은 [UI 표준](../../ui-standards.md)이 우선한다. 이 와이어프레임은 정보 구조·흐름·상태의 근거다. 소득공제 화면에 옮긴 기준은 [구현 계획](../plans/2026-11-11-tax-implementation.md)의 "UI 표준 적용 (PR 5~7)" 절.

## 화면

### A. 공통 셸 · 메뉴

- 목적: 메뉴 개편 결과, 역할별 노출, 소득공제 메뉴의 진입 화면을 확인한다.
- 영역
  - 데스크톱 사이드바: 홈 | 소득공제[입력자료 / 분석·지출계획 / 연도별 세법 관리(관리자만)] | 대시보드[대분류 / 소분류] | 거래 목록 | 그룹 관리. "업로드" 없음.
  - 375px 하단 탭 5칸: 홈·소득공제·대시보드·거래·그룹.
  - 소득공제 화면 안 탭: 375px에서만. 회원 2개, 관리자 3개. 세 번째 라벨은 **"세법 관리"**(결정 2026-11-12). 사이드바와 화면 제목은 "연도별 세법 관리"를 유지한다. 데스크톱은 사이드바 2단 메뉴로 이동한다.
  - 헤더: 기존과 같다(그룹 선택). 소득공제 화면 머리에 "개인 자료 · 그룹과 무관" 표시.
  - 탭 라벨 기록: "결정: 세법 관리 (2026-11-12)"와 탭 모양 하나. 두 안 비교와 줄 수 측정은 없앴다.
- 소득공제 메뉴를 누르면(D16): 선택 연도에 연도 기록이 있으면 분석·지출계획 ① 현황, 없으면 입력자료로 간다.
  선택 연도는 소득공제 화면이 기억하는 귀속연도, 없으면 올해다.
  - 확인 방법: 상태 컨트롤에서 상태를 고르고 사이드바·하단 탭의 "소득공제"를 누른다. A 화면의 [눌러 보기] 버튼 3개도 같은 동작이다.
  - 상태 "연도 기록 없음"·"자료 없음"은 입력자료로, 나머지 상태(미완료 포함)는 ① 현황으로 간다.
- 대시보드·거래·그룹 메뉴는 범위 밖이라 눌리지 않는다.

### B. 홈 (개편)

- 목적: 업로드 메뉴가 없어진 뒤 홈에서 등록 현황·업로드·이력을 모두 처리하는지 확인한다.
- 영역
  - 지난달 내 요약 카드: 기존 그대로(수입·지출).
  - 월별 등록 현황: 머리에 연도 이동(◀ 2026년 ▶)과 그 오른쪽 업로드 이력 아이콘 버튼. 월 칸 12개(등록됨 / 미등록 · 업로드하기 / 예정).
  - 없앤 것: "지난달 업로드" 카드, "파일 올리기" 카드.
- 창: 업로드 이력(기존 목록과 같은 항목), 미등록 월 → 업로드 창, 등록 월 → 데이터 관리 창. 뒤의 둘은 기존과 같아 제목·라벨만 그렸다.
- 375px는 **지난달 요약 → 월별 등록 현황** 순으로 쌓는다(D24). 데스크톱 2단(현황 넓게 왼쪽 | 요약 오른쪽)은 그대로 뒀다.
  HTML 문서 순서는 375px 순서(요약 → 현황)이고 데스크톱에서만 격자 위치로 현황을 왼쪽에 둔다.

### C. 소득공제 › 입력자료

- 목적: 귀속연도 하나의 기본정보와 누계자료를 넣고 합계를 확인한다.
- 영역(위에서 아래)
  1. 귀속연도 선택(올해·전년도·다음 해), 개인 자료 표시
  2. 기본정보: 예상 총급여·근로기간·자녀등 수, [수정]
  3. 신용·체크 자료: 카드사별 목록(기준일·합계·메모·완료/미완료), [신용·체크 자료 추가], 건별 [편집] [삭제]
  4. 현금영수증 자료: 연도 1건, [편집]만 있고 삭제는 없다(D19). 입력 전에는 "미완료 · 4칸 빔"과 [4칸 0원으로 채우기]
  5. 연도 합계표(결제수단 3 × 소비구분 4)와 경고(미입력·기준일 불일치)
  6. 연도 기록 삭제
- 데스크톱은 왼쪽(2~4) | 오른쪽(5) 2단, 375px는 번호 순서대로 쌓는다.
- 창: 모든 폭에서 가운데 창(Dialog)이다(D26). 좁은 화면에서도 아래에서 올라오는 창(BottomSheet·ResponsiveOverlay)을 쓰지 않는다. 다른 화면의 창도 같다.
  - 기본정보 수정: 총급여, 근로기간(시작월~종료월), 자녀등 수와 요건 3가지 안내
  - 카드사 자료 편집: 카드사명·기준일·메모, 8칸 표, [빈 칸 0원으로 채우기]
  - 현금영수증 자료 편집: 기준일·메모, 4칸
  - 자료 삭제 확인: 확인 한 번
  - 연도 기록 삭제 확인(D22): 함께 지워지는 범위를 적고, **귀속연도(2026)를 직접 입력해야 [삭제]가 켜진다.** 다른 값이면 꺼진 채다. 창을 다시 열면 입력이 비워진다.
- 375px 배치(AC-23)
  - 8칸 입력: 행 = 소비구분 4, 열 = 신용카드 / 체크카드. 입력 2열이라 가로 스크롤이 없다.
  - 4칸 입력: 행 = 소비구분 4, 열 1개.
  - 연도 합계표: 행 = 소비구분 4 + 합계, 열 = 신용카드 / 체크카드 / 현금영수증. 행 합계 열은 없애고 소비구분 이름 아래 "계 n"으로 옮겼다. 데스크톱은 합계 열을 둔다.

### D. 소득공제 › 분석·지출계획 (단계형)

- 목적(주 목적): 현재 지출 현황을 보고, 남은 기간 어느 결제수단으로 쓰면 소득공제액이 커지는지 판단한다.
- 구조(D23): 모든 폭에서 ① 현황 → ② 지출계획 → ③ 추천을 한 번에 한 단계씩 본다. 단계 탭으로 바로 옮길 수 있고 아래에 [이전] [다음]이 있다.
  데스크톱도 1단이며 가운데 정렬·최대 폭 720px로 그렸다(폭 값은 가정). 개요형 화면과 방향 선택은 없앴다.
- 단계 위 공통: 귀속연도 선택, 개인 자료 표시, 상태 알림(새 세법 버전·추정·근로기간), 적용 세법(귀속연도·버전·적용일)·자료 기준일·예상 총급여 한 줄
- ① 현황
  - 현재 요약 4칸: 현재 소득공제액(환급액 아님) / 최저사용금액 달성 / 기본한도 사용 / 추가한도 사용
  - 소비구분별·결제수단별 사용 비율(분모 = 전체 입력 공제대상액을 문장으로 명시)
  - [계산 과정 보기] (D20): 기본은 접혀 있다. 펼치면 1. 최저사용금액 차감 → 2. 공제율 → 3. 한도 순서의 단계 표가 나온다.
  - 참고: 기본한도까지 남은 공제 여유. 소비를 늘리라는 문구는 없다.
- ② 지출계획
  - 소비구분 4행 × (신용카드 고정 / 체크카드·현금영수증 고정 / 바꿀 수 있음), 합계 자동
  - [계산하기] (D18): 지출계획을 저장하고 추천을 다시 계산한다. 입력 중에는 자동으로 다시 계산하지 않는다. 와이어프레임에서는 누르면 ③으로 옮긴다.
  - 375px에서 표는 소비구분별 묶음(라벨 + 입력 3줄 + 합계)으로 쌓는다.
- ③ 추천
  - "현재 계획: 지금까지의 결제수단 비율(신용 82.0% · 체크 14.6% · 현금 3.4%)" 한 줄(D17). 이 비율은 연도 전체 값이다.
  - 표의 현재 계획 금액은 바꿀 수 있는 금액을 소비구분마다 그 소비구분의 지금까지 신용카드 : 체크카드 : 현금영수증 입력액 비율로 나눈 값이다.
    원 미만은 내리고 남는 원은 신용카드에 더한다.
  - 현재 계획 vs 추천 배분, 남은 기간 총액(두 열이 같다), 연말 예상 소득공제액, 현재 계획 대비 차이, 이유, 가정. "차이 없음" 상태
- 미완료·자료 없음·세법 준비 중(D25): ② 입력은 열려 있고 [계산하기]는 저장만 한다. ①은 숫자 대신 안내를 보인다.
  - 자료 미완료(자료 없음 포함): ③ 자리에 "자료를 완료하면 계산합니다", 빈 칸 수, [입력자료로 가기].
  - 자료는 완료됐고 세법 준비 중: ③ 자리에 "세법 준비 중"만 보인다. 빈 칸 수와 입력자료 버튼은 없다.
- 연도 기록 없음: 기록이 없어 지출계획도 저장할 수 없으므로 화면 전체가 입력자료로 가는 안내다.

화면에 쓴 숫자(합성값, PRD 7.1절 산식)

- 입력: 총급여 50,000,000 / 일반 신용 14,000,000 · 체크 2,000,000 · 현금 500,000 / 전통시장 300,000 · 200,000 · 100,000 / 대중교통 200,000 · 300,000 · 0 / 문화체육 100,000 · 100,000 · 0. 합 17,800,000.
- 현재: A = 14,000,000, B = 2,500,000, M = 200,000, T = 600,000, P = 500,000. 최저사용금액 L = 12,500,000 ≤ A이므로 차감액 = 1,875,000.
  공제 가능 금액 = 2,100,000 + 810,000 + 440,000 − 1,875,000 = 1,475,000. 기본한도 3,000,000 이하라 소득공제액 1,475,000원.
- 지출계획: 일반 500,000 / 300,000 / 1,200,000, 전통시장 0 / 100,000 / 100,000, 대중교통 100,000 / 0 / 0, 문화체육 0 / 0 / 100,000. 총액 2,400,000.
- 현재 계획의 배분
  - 일반 1,200,000 × (14,000,000 : 2,000,000 : 500,000) → 1,018,181 / 145,454 / 36,363, 남는 2원을 신용카드에 → 신용 1,018,183
  - 전통시장 100,000 × (300,000 : 200,000 : 100,000) → 50,000 / 33,333 / 16,666, 남는 1원 → 신용 50,001
  - 문화체육 100,000 × (100,000 : 100,000 : 0) → 50,000 / 50,000 / 0
- 현재 계획 연말: A = 15,518,183, B = 2,981,817, M = 300,000, T = 800,000, P = 600,000 (합 20,200,000).
  2,327,727.45 + 984,545.10 + 560,000 − 1,875,000 = 1,997,272.55 → 원 미만 버림 **1,997,272원**.
- 추천 배분 연말(일반 1,200,000을 모두 체크카드·현금영수증으로): A = 14,500,000, B = 4,000,000, M = 300,000, T = 800,000, P = 600,000 (합 20,200,000).
  2,175,000 + 1,290,000 + 560,000 − 1,875,000 = **2,150,000원**. 차이 **+152,728원**.

### E. 소득공제 › 연도별 세법 관리 (관리자)

- 목적: 관리자가 귀속연도별 세법 수치를 초안으로 만들고 검증해 적용한다.
- 영역
  - 귀속연도 목록: 2027(적용 버전 없음) / 2026(적용 v1 · 초안 2개) / 2025(등록 안 함)
  - 버전 목록(D21): v3 초안, v2 초안, v1 적용. 작성자·적용자·시각 표시.
    - [새 초안 만들기]는 초안이 있어도 늘 켜져 있다. 번호는 만들 때마다 늘고 다시 쓰지 않는다.
    - 초안마다 [삭제]가 있고 확인은 한 번이다. 적용본에는 삭제가 없다.
  - 버전 상세: 최저사용금액 비율, 급여구간 경계 금액, 공제율 5종, 기본한도(급여구간 2 × 자녀등 0/1/2명 이상), 추가한도 상한(구간별), 계산 알고리즘 버전(고정), 근거(법령명·조문·URL)·적용 대상 기간·메모
  - 초안: [초안 저장] [검증] [적용]. 적용 확인 창에 "다른 초안은 초안으로 남습니다"를 적었다.
  - 적용본: 모든 입력이 꺼진 읽기 전용.
- 데스크톱은 목록(1) | 상세(2) 2단, 375px는 연도 → 버전 → 상세 순으로 쌓는다.
- 회원 보기로 열면 "권한 없음" 화면이 나온다.
- 동작하는 것: v1/v2/v3 전환, 검증 버튼, 적용 확인 창, 초안 삭제 확인 창. 연도 전환, 새 초안 만들기, 실제 삭제는 그리지 않았다(2026년만).

## 결정됨 (2026-11-12)

이전 검토본의 열린 질문 13개는 모두 결정됐다. 번호는 이전 질문 번호다.

1. 소득공제 메뉴 진입: 선택 연도에 연도 기록이 있으면 분석·지출계획 ① 현황, 없으면 입력자료 (D16) → A
2. 추천의 "현재 계획" = 지금까지의 결제수단 비율대로 쓴다고 본다 (D17) → D ③
3. 지출계획은 [계산하기] 버튼으로 저장하고 다시 계산한다. 입력 중 자동 재계산 없음 (D18) → D ②
4. 현금영수증 자료는 편집만, 삭제 없음 (D19) → C
5. 공제액이 나온 과정은 접힌 영역 [계산 과정 보기] (D20) → D ①
6. 세법 초안은 귀속연도마다 여러 개. 초안은 삭제할 수 있고 적용본은 삭제할 수 없다 (D21) → E
7. 연도 기록 삭제는 귀속연도를 직접 입력해야 [삭제]가 켜진다 (D22) → C
8. 좁은 화면 탭 라벨은 "세법 관리". 화면 제목·사이드바는 "연도별 세법 관리" (D01) → A
9. 분석·지출계획은 모든 폭에서 단계형 (D23) → D
10. 375px 홈은 지난달 요약 위, 월별 등록 현황 아래 (D24) → B
11. 미완료·세법 준비 중에도 지출계획 입력은 열고 추천·결과만 숨긴다 (D25) → D
12. 좁은 화면 입력 창도 항상 가운데 창(Dialog) (D26) → 모든 창
13. PRD의 "제안" 요구사항과 7.1·7.2 정책 모두 확정 → 점선·"제안" 표식 삭제

## 검증 결과

2026-11-12, 앱 내장 브라우저에서 HTML 파일을 직접 열어 다시 확인했다.

- 가로 넘침: 폭 × 보기 2 × 화면 5(A·B·C·D·E) × 상태 16 조합을 스크립트로 돌렸다. D는 3단계 각각([계산 과정 보기]를 펼친 채), E는 v1·v2·v3 각각.
  화면 틀 밖으로 나가는 요소, 안쪽에서 넘치는 상자, 페이지 가로 스크롤을 찾았다. 1280px 뷰포트(데스크톱·375px 틀) 260건, 375px 뷰포트 130건 모두 0건.
  창 10개도 375px(폭 343px)와 1280px(폭 560px)에서 넘침 0건이고 모두 화면 가운데에 뜬다.
- 누름 경로: 소득공제 메뉴 진입(기본·미완료 → ① 현황, 자료 없음·연도 기록 없음 → 입력자료), A의 [눌러 보기] 3개, 좁은 화면 탭 라벨 "세법 관리"와 화면 제목 "연도별 세법 관리",
  375px 홈 순서(요약 위)와 데스크톱 2단(현황 왼쪽), 연도 기록 삭제(빈 값·2025 → 꺼짐, 2026 → 켜짐, 다시 열면 꺼짐), 미완료에서 ② 입력표 표시와 ③ 안내,
  [계산하기] → ③, v1 읽기 전용, v2·v3 초안 삭제 확인 창, 적용 확인 창 문구를 확인했다. 콘솔 오류 없음.
- 위 전체 점검 뒤에 ③의 "세법 준비 중" 문구와 현재 계획 비율 한 줄(연도 전체 비율)을 고쳤다. 그 뒤에는 375px에서 D 화면 5개 상태 × 3단계(15건)만 다시 돌렸고 넘침 0건, 콘솔 오류 없음. 1280px 전체 점검은 다시 돌리지 않았다.
- D 데스크톱: 본문 폭 720px, 가운데 정렬.
- 숫자: 위 D 절의 값을 PRD 7.1절 산식을 옮긴 스크립트로 다시 계산했다. PRD 합성 예시 1(1,950,000원)이 같은 스크립트에서 맞는 것을 먼저 확인했다.
- 확인하지 못한 것: 화면 읽기 프로그램, 다른 브라우저, 실제 앱 글꼴·부품에서의 폭(탭 라벨 "세법 관리" 포함), 다크 모드. 키보드 포커스 순서는 이번에 다시 보지 않았다(2026-11-11 확인 뒤 기본 `<button>`·`<details>`·`<input>`만 더했다).
