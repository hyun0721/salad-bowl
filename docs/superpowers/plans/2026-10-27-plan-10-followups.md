# Plan 10 후속 과제

Plan 10(대시보드 도넛을 ECharts로 교체)의 Task 리뷰, 브라우저 측정, 최종 리뷰에서 나왔지만 넘긴 항목과 다음 과제다.

## 실행 중 바뀐 결정 (기록용)
- **라벨 정렬**: 설계의 `alignTo: 'labelLine'`은 작은 조각이 몰리면 지시선이 한 세로줄로 모여 겹쳤다. `'none'`으로 바꿔 라벨을 조각 가까이에 두고 ECharts가 세로로 밀어내게 했다(`labelLine.length` 10, `length2` 8).
- **시작 각도**: 5% 미만 조각이 4개 이상이면 그 묶음의 가운데가 9시 방향에 오도록 돌린다(`donutStartAngle`). 12시에 몰리면 라벨이 위쪽 좁은 곳에 쌓여 지시선이 한데 모였다. 그 밖에는 12시에서 시작한다.
- **가운데 금액 크기**: 금액이 길면(예: ₩ 21,480,000) 도넛 구멍을 넘어 조각에 가려졌다. 높이 기준 안쪽 지름에 맞게 글자 크기를 줄인다(`centerValueSize`, 9~18px).
- **높이**: 넓은 화면 기본 260, 좁은 화면 220, 6개를 넘으면 조각당 +12, 상한 380(`donutHeight`).
- **메모이제이션**: 호버할 때마다 차트를 다시 그리던 문제(새 `slices`·`onEvents` 객체)를 `useMemo`로 고쳤다.
- **수입·지출 카드**: 320px에서 큰 금액이 카드를 넘어 가로 스크롤이 생겼다(Plan 간격 축소 PR에서 생긴 문제). 카드를 `auto-fit`으로 바꿔 아주 좁은 폭에서는 한 줄에 하나씩 두고, 글자는 `clamp(16px, 4.6vw, 20px)`.
- **Task 3 문서 작업**은 계획의 Codex luna 대신 컨트롤러가 직접 했다(측정값을 그대로 옮기는 일이라).

## 브라우저 측정 (Playwright + 시스템 Chrome, 실제 렌더링 좌표)
1200·375·320px × 데이터 5종(꼬리형 60·10·5·4·3·3·2·2·2·2·1·1, 밀집형, 고르게 12개, 3개, 1개) × 라이트·다크, 30가지.

| 항목 | 교체 직후 | 최종 |
|---|---|---|
| 지시선끼리 교차 | 꼬리형에서 최대 26 | 0 |
| 지시선끼리 겹쳐 지나간 길이 | 꼬리형 1200px 480px | 합계 24px(고르게 12개 320px에서 12px씩) |
| 라벨이 카드 밖으로 잘림 | 0 | 0 |
| 비율이 `…`에 묻힘 | 0 | 0 |
| 가로 스크롤 | 320px 2건 | 0 |
| ECharts 콘솔 경고 | 언마운트 때 "disposed" | 0 |
| 선이 다른 라벨 상자를 스침 | 0 | 6(모두 고르게 12개, 화면으로 보면 겹치지 않음. 측정이 상자 가장자리를 셈) |

- 조각 호버(커짐·나머지 흐림·툴팁), 목록 행 호버 → 조각 강조, 행 클릭 → 거래 모달을 라이트·다크에서 확인했다.

## 실기기·눈으로 확인 (사용자가 직접)
- iOS Safari·Android Chrome에서 조각 터치 시 툴팁과 모달이 함께 뜨는 모습, 작은 조각 터치 정확도(작으면 목록 행을 쓴다).
- 다크 모드에서 빗금 무늬(9번째 조각부터)가 보이는지.
- 스크린리더가 차트를 건너뛰고 목록 행을 읽는지(차트는 `aria-hidden`).
- 대시보드를 처음 열 때 느려졌는지(대시보드 청크 gzip +154.6 kB).

## 다음 과제
- **꺾은선 차트**: `common/echarts.ts`에 `LineChart`·`GridComponent` 등록을 더하고 `EChart`를 그대로 쓴다. 축 툴팁(`trigger: 'axis'`)으로 그 달의 모든 대분류 값을 한 상자에 보인다.
- **비교군 선택**: 특정 대분류만 골라 비교한다. 도넛에서 "고른 것끼리 비율"과 "전체 대비 비율(나머지는 회색)" 중 무엇을 보일지 먼저 정한다. 비교군을 바꿀 때 ECharts 전환 애니메이션이 돈다(2개로 줄일 때 중간 프레임이 끊겨 보이면 `animationTypeUpdate` 조정).

## 나중에 (사소함, 리뷰에서 넘긴 것)
- `useChartTheme`이 `window.matchMedia`를 가드 없이 부른다(테스트 setup이 채운다).
- `EChart`의 `useImperativeHandle`이 초기화 순서에 기댄 `!` 단언이다.
- 차트 위아래 빈 공간이 조금 남는다(좁은 화면 약 60px). `donutHeight` 계수를 더 줄일 수 있다. **(Plan 14에서 처리)**
- 모바일 대시보드에서 RAC "Dialog 제목" 콘솔 경고가 난다(이번 변경 전부터 있던 것으로 보임, 추측). **(Plan 14에서 처리)**
- (최종 리뷰) `EChart.test.tsx`의 StrictMode 테스트가 두 번의 init에 같은 가짜 객체를 돌려줘, ref가 두 번째 인스턴스를 가리키는지 실제로는 확인하지 않는다.
- (최종 리뷰) 테마가 바뀌면 `DonutChart`가 `setOption`을 다시 부르는지 보는 통합 테스트가 없다(훅 테스트와 memo 의존성으로 간접 보장). 가운데 두 줄 겹침 검사가 테스트에 두 번 있다.
- `centerValueSize`는 차트 폭이 높이보다 넓다고 가정한다. 폭이 더 좁으면 구멍이 더 작아진다.
