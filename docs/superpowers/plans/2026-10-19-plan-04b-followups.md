# Plan 04b 후속 과제

Plan 04b(홈·업로드·거래 화면)의 Task별 리뷰, 최종 리뷰, 로컬 브라우저 확인에서 나왔지만 이후 계획으로 넘긴 항목이다. [04a 후속 과제](2026-10-19-plan-04a-followups.md)와 함께 본다.

## 04b에서 바로잡은 것 (기록용)
- **업로드·수정 이력 시각**: `importedAt`·`changedAt`은 서버가 UTC(`…Z`)로 돌려준다. `formatInstant`(Asia/Seoul)로 바꿔 9시간 이른 시각이 보이던 문제를 고쳤다. `occurredAt`은 시간대 없는 한국 시간이라 `formatDateTime`을 그대로 쓴다.
- **화면 오류 처리 규칙**: 계획서의 화면 코드와 Global Constraints가 다를 때는 Global Constraints를 따른다(사용자 결정). 모든 쿼리는 실패하면 오류 문구와 "다시 시도"를 보여주고, 한 화면에 재시도 버튼이 여럿이면 이름을 다르게 한다(예: "요약 다시 시도").

## Plan 04c (그룹 화면·초대·PWA·Pages 프록시)

### 04a에서 넘어온 것 중 아직 남은 항목
- **세션 복원 실패 표시**: 복원 재시도가 끝나도 일시적 실패(5xx·네트워크)면 로그인 화면이 나온다. "서버에 연결하지 못했습니다 + 다시 시도" 상태로 바꾼다.
- **화면 전환 시 포커스 이동**: `document.title`은 바뀌지만 포커스는 옮기지 않는다. 경로가 바뀌면 `h1`로 포커스를 옮긴다.
- **inline style 정리**: `PublicOnly`, `RequireAuth`, `PagePlaceholder`에 남아 있다. CSS Modules로 옮긴다.
- **레이아웃 breakpoint**: `AppLayout`은 아직 720px이다. 새 화면들(820px)과 맞춘다.
- **헤더 "그룹 없음" 링크**의 누르는 영역(40px 이상)을 확인한다.
- **AbortError 구분**과 04a 테스트 보강 항목(로그인 가드 `next` 보존, `onAuthLost` 캐시 비우기, `GroupProvider` 오프라인, signup 오류 매핑).

### 04b에서 나온 것
- **대화상자(Modal) 포커스**: 닫을 때 원래 위치(달력 칸)로 포커스를 돌려주지 않는다. Tab으로 대화상자 밖으로 나갈 수 있고, Esc는 대화상자 요소에만 걸려 있다. 포커스 복귀·가두기를 넣는다. 업로드 중에는 닫기를 막는 것도 검토한다(닫아도 캐시 무효화는 훅에서 하므로 데이터는 맞다).
- **그룹에서 추방됐을 때**: 그룹 거래·그룹 상세가 403 `REMOVED_FROM_GROUP`이면 일반 오류만 보인다. `['groups']`를 무효화해 헤더에서 그 그룹을 빼고 안내한다. 그룹 대시보드를 만들 때 함께 처리한다.
- **월 입력**: Firefox·데스크톱 Safari는 `type="month"`를 일반 글자 칸으로 보여준다. 덜 입력된 값이면 쿼리가 꺼진 채 "불러오는 중입니다."가 계속 보인다. 형식 안내를 보여주거나 홈처럼 이전·다음 달 버튼을 둔다.
- **거래 범위 버튼**: 그룹 거래를 보다가 선택 그룹이 없어지면 데이터는 내 거래로 바뀌지만 "그룹 거래" 버튼이 눌린 상태로 남는다. `aria-pressed`를 실제 범위에서 계산한다.

## 화면 다듬기 (디자인 보완 때)
- **비활성 버튼 모양**: 파일을 고르기 전 "업로드" 버튼은 비활성이지만 브라우저에서 활성 버튼과 거의 같아 보인다. `:disabled` 스타일을 더 분명하게 한다.
- **커버리지 달력 글자 줄바꿈**: 1024px 폭에서 "미등록 · 업로드하기"가 칸 안에서 어색하게 끊긴다. 좁은 칸에서는 "미등록"만 보이고 업로드 안내는 접근성 이름으로 두는 방법이 있다.
- **상세 패널 위치**: 콘텐츠 폭이 약 904px보다 좁으면 패널이 목록 아래로 내려간다. 포커스 이동으로 스크롤은 되지만, 태블릿 폭에서는 덮개(sheet) 형태를 검토한다.
- **글자·간격 리터럴**: 토큰에 글자 크기 단계가 없어 `font-size` 리터럴이 남아 있다. `gap: 4px`(`ui.module.css`), `padding: 14px`(`CoverageCalendar.module.css`), 대화상자 배경색 `rgb(...)` 리터럴도 있다. 토큰(`--space-1`, overlay 색)을 추가해 옮긴다.
- **연도 이동 버튼**: `‹ ›` 글자 대신 인라인 SVG 아이콘을 쓴다(아이콘 세트 작업과 함께).

## 나중에 (사소함)
- **테스트 환경의 `File`·`FormData` 교체**: `src/test/setup.ts`가 전역으로 Node 구현으로 바꾼다(jsdom 파일이 multipart에서 `blob`으로 이름이 바뀌는 문제). 업로드 테스트에만 `vi.stubGlobal`로 좁히거나, `new FormData(form)`·`FileReader`를 테스트에서 쓸 수 없다는 점을 주석에 적는다.
- **업로드 폼**: 끌어다 놓기(`onDrop`) 테스트가 없다. 업로드 성공 뒤에도 파일이 선택된 채 남는다. 파일 선택 창을 취소하면 직전 결과가 사라진다. `UploadForm`의 `onDone` prop은 쓰는 곳이 없다.
- **상세 패널**: "저장했습니다."가 다시 고치는 동안에도 남아 있다. 수정 이력 목록이 `key={i}`다.
- **테스트 빈틈**
  - 숨김 토글 요청 본문, 바뀐 것 없이 저장, 수정 실패 문구
  - 다른 멤버 거래를 고치는 관리자(숨김·삭제가 보이지 않아야 함)
  - 요약의 숨긴 거래 포함, 다음 연도의 "예정" 칸
  - 커버리지 연도 경계(1, 9999 허용, 10000 거부)
  - `renderPage`·`usePageTitle` 직접 테스트
- `errorMessage`의 기본 문구 리터럴이 반복된다(`FALLBACK` 상수). `format.ts`는 `NaN`을 따로 처리하지 않는다.
- 로그인한 상태에서 페이지를 새로 고치면 콘솔에 401 두 건이 찍힌다. 세션 복원 과정에서 나오는 것으로 보이고 화면 동작에는 문제가 없다. 어느 요청인지 확인하고, 필요 없는 요청이면 없앤다.
