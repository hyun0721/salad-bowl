# Plan 16a 후속

## 바뀐 결정
- 별도 결정 변경은 확인되지 않았다. 홈에는 지난달 업로드 상태와 요약을 두고, 월별 등록 현황과 월별 관리는 업로드 메뉴로 옮겼다.

## 실제 앱에서 확인한 것
- 빌드 `353d5b9`와 검증 스택에서 확인했다. seed는 2026년 7~9월에 각 6건을 등록했다.
- 모바일(375×812) 홈에서 `지난달 업로드`가 `2026년 9월 데이터 등록됨 · 6건`으로 보였고 `월별 등록 현황`과 `최근 업로드`는 없었다.
- 모바일 업로드 화면 순서는 `월별 등록 현황` → `파일 올리기` → `업로드 이력`이었다.
- 모바일 `/upload?month=2026-06`에서 `2026년 6월 데이터 업로드` 창이 열리고 주소가 `/upload`로 바뀌었다. 새로고침하면 창이 다시 열리지 않았다.
- 달력에서 2026년 9월 데이터를 삭제한 뒤, 홈에 `2026년 9월 데이터가 아직 없습니다.`와 `업로드하기` 링크가 나타났다. 링크를 누르면 `/upload`에서 `2026년 9월 데이터 업로드` 창이 열렸다.
- 데스크톱 홈의 미등록 카드와 사이드바 레이아웃을 확인했다. `/upload?month=2026-09`에서도 해당 업로드 창이 열리고 주소가 `/upload`로 바뀌었다.

## 확인하지 못한 것
- 내장 브라우저에서 OS 파일 선택기를 조작할 수 없어 파일 업로드 제출은 확인하지 못했다.
- 데스크톱에서 월별 메뉴 순서, 등록 상태의 관리 창, 그리고 삭제 후 홈 링크까지 확인했는지는 기록에 없다.

## 넘긴 항목
- `CoverageSection.test.tsx` 파일 끝의 `})})` 및 EOF 개행 누락.
- coverage 실패 테스트에서 요약이 계속 렌더링되는 독립성 확인이 절반만 되어 있음.
- coverage 로딩 문구 테스트가 없음.
- `CoverageSection.tsx:34`의 계획된 effect로 인한 oxlint `react(set-state-in-effect)` 경고.
- 인라인 `onInitialMonthHandled`가 렌더마다 effect를 다시 실행함. 현재는 무해하며 `useCallback` 적용 여부는 후속 검토 가능.
- 잘못된 월(예: `2026-13`) 처리 분기 테스트가 없음.
- 비정상적으로 과거인 월(예: `0000-01`)은 0년을 초기 연도로 만들며 query parameter가 지워지지 않을 수 있음.
- `UploadPage`가 이미 마운트된 뒤 `?month=`가 설정되면 초기 월을 다시 읽지 않음. 현재 동선에서는 도달할 수 없음.
