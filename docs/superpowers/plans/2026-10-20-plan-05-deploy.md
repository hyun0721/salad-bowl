# Plan 05 — 배포 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 이 저장소에서는 `.claude/skills/codex-collab` 규칙으로 Task마다 구현자(Claude/Codex)를 정한다.

**Goal:** Salad Bowl을 무료 티어(Cloudflare Pages + Render + Supabase)에 배포할 수 있게 만든다. 배포를 막는 문제(업로드 크기와 파싱 메모리, 운영 설정)를 고치고, 컨테이너·배포 설정·설정값 동기화·점검 스크립트·배포 절차서를 갖춘 뒤, 사용자와 함께 실제로 배포하고 확인한다.

**Architecture:**
- 브라우저 → Cloudflare Pages(정적 파일 + `/api/*` Function) → Render(Docker, Spring Boot) → Supabase Postgres(세션 풀러).
- 빌드·배포는 플랫폼의 Git 연동을 쓴다. `main`에 머지되면 Pages와 Render가 각자 빌드·배포한다.
- **설정값의 원본은 GitHub 저장소의 Environment `production`**(Secrets·Variables)이다. 수동 실행 워크플로 `sync-config`가 그 값을 Render와 Cloudflare Pages에 넣는다. 배포 플랫폼을 바꾸면 이 워크플로의 대상만 바꾼다. 저장소 파일에는 비밀값을 두지 않는다(공개 저장소).
- Render 서비스 정의는 저장소의 `render.yaml`(Blueprint)에 둔다.

**Tech Stack:** Spring Boot 4.1.1 / Java 21, Apache POI 5.4.1(그대로), Docker(eclipse-temurin 21), Vite 8 / Cloudflare Pages Functions, GitHub Actions, Render API, Cloudflare API.

**선행 조건:** Plan 04c(PR hyun0721/salad-bowl#7)가 머지되어 있다. `main`에서 `feat/plan-05-deploy` 브랜치를 딴다.

**범위 밖:**
- **고도화**: 대용량 엑셀 스트리밍 파싱(`가계부 내역` 시트만 행 단위로 읽기). 지금은 업로드를 최대 3개월치·512KB로 제한해 XSSF로도 안전한 크기로 묶는다. 한도를 넓힐 때 스트리밍으로 바꾼다([잔여 작업](../../backlog.md)에 기록).
- **Plan 06 "운영·보안 보강"**:
  - 인증: refresh 토큰 서버 측 폐기(`token_version`)와 진행 중인 refresh가 로그아웃을 되돌리는 클라이언트 경합(04a 후속에서 함께 넘어온 항목), 로그인 횟수 제한
  - 데이터: 낙관적 락(`@Version`), `lock_timeout`, 무결성 오류 매핑, import 일괄 삽입(IDENTITY라 JDBC batch 불가)과 동시 import 처리(지금은 깨끗하게 409로 롤백된다)
  - 기타: 초대 정리·발급 제한, 관리자 위임, 프레임워크 4xx `detail` 노출 정책(지금은 그대로 둔다)

## Global Constraints

- **새 의존성을 추가하지 않는다**(API·웹 모두). GitHub Actions는 `actions/checkout@v4` 외의 서드파티 액션을 쓰지 않는다(API 호출은 `curl`).
- **비밀값을 저장소에 넣지 않는다.** 예시는 `<...>` 자리표시로 쓰고, 실제 값은 GitHub Environment `production`에만 넣는다. 워크플로는 비밀값을 출력하지 않는다(`set -x` 금지, 응답 본문에 비밀값이 섞일 수 있는 호출은 본문을 버린다). 테스트용 xlsx는 코드로 만든다. 실제 뱅크샐러드 파일과 개인 데이터는 쓰지 않는다.
- **로컬 개발은 그대로 동작해야 한다.** 기본 프로필(`application.yml`)의 기본값과 `docker compose` + `bootRun` + `npm run dev` 흐름을 깨지 않는다.
- API 오류 응답은 기존 `ApiException(ErrorCode, message)` → `{code, message}` 규칙을 따른다. 예외 원인(cause)은 응답에 내보내지 않는다.
- 문서는 한국어. 문서 문체는 기존 docs처럼 "~한다"체, 화면 문구는 합니다체.
- 커밋 메시지 끝에 `Co-Authored-By: <구현 모델> <noreply@…>`(Claude: `noreply@anthropic.com`, Codex: `noreply@openai.com`).
- **구현자 배정(codex-collab):** `apps/api`·Docker Task(1, 3, 4)는 Claude, 웹·워크플로·스크립트·문서 Task(2, 5, 6, 7)는 Codex. 리뷰는 구현하지 않은 쪽이 한다.

```java
import com.saladbowl.api.importer.ImportDtos.ImportBatchView;
import com.saladbowl.api.importer.ImportDtos.ImportResult;
import org.springframework.stereotype.Service;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.transaction.support.TransactionTemplate;

import java.io.InputStream;
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.List;

@Service
public class ImportService {

    /** 한 파일의 첫 거래일과 마지막 거래일 차이의 상한(약 3개월). 7/1~9/30, 7/20~10/19 같은 "3개월" 범위를 받는다. */
    static final long MAX_PERIOD_DAYS = 92;

    private final BanksaladParser parser;
    private final MergeService mergeService;
    private final ImportBatchRepository batches;
    private final TransactionTemplate transaction;

    public ImportService(BanksaladParser parser, MergeService mergeService, ImportBatchRepository batches,
                         PlatformTransactionManager transactionManager) {
        this.parser = parser;
        this.mergeService = mergeService;
        this.batches = batches;
        this.transaction = new TransactionTemplate(transactionManager);
    }

    /**
     * 파일 하나를 하나의 트랜잭션으로 반영한다. 파싱과 기간 검사는 DB 커넥션을 잡기 전에 끝낸다
     * (형식·기간 오류면 아무것도 쓰지 않고, 풀러 연결을 파싱 시간 동안 붙잡지 않는다).
     */
    public ImportResult importFile(long ownerId, String fileName, InputStream in) {
        List<ParsedRow> rows = parser.parse(in);
        checkPeriod(rows);
        return transaction.execute(status -> {
            ImportBatch batch = batches.save(new ImportBatch(ownerId, fileName));
            MergeService.MergeCounts counts = mergeService.merge(ownerId, batch.getId(), rows);
            batch.record(rows.size(), counts.created(), counts.updated(), counts.unchanged());
            return new ImportResult(batch.getId(), rows.size(), counts.created(), counts.updated(), counts.unchanged());
        });
    }

    private static void checkPeriod(List<ParsedRow> rows) {
        if (rows.isEmpty()) {
            return;
        }
        LocalDate first = rows.getFirst().data().occurredAt().toLocalDate();
        LocalDate last = first;
        for (ParsedRow row : rows) {
            LocalDate day = row.data().occurredAt().toLocalDate();
            if (day.isBefore(first)) {
                first = day;
            }
            if (day.isAfter(last)) {
                last = day;
            }
        }
        if (ChronoUnit.DAYS.between(first, last) > MAX_PERIOD_DAYS) {
            throw new ApiException(ErrorCode.IMPORT_PERIOD_TOO_LONG,
                    "transactions span " + first + " to " + last + "; at most " + MAX_PERIOD_DAYS + " days per file");
        }
    }

    @Transactional(readOnly = true)
    public List<ImportBatchView> recent(long ownerId) {
        return batches.findTop20ByOwnerIdOrderByImportedAtDescIdDesc(ownerId).stream()
                .map(ImportBatchView::from)
                .toList();
    }
}
```

```java
 */
@ConfigurationProperties(prefix = "app.auth.refresh-cookie")
public record RefreshCookieProperties(String path, String sameSite, boolean secure) {

    private static final Set<String> SAME_SITE_VALUES = Set.of("Strict", "Lax", "None");

    public RefreshCookieProperties {
        if (path == null || !path.startsWith("/")) {
            throw new IllegalArgumentException("app.auth.refresh-cookie.path must start with /");
        }
        if (!SAME_SITE_VALUES.contains(sameSite)) {
            throw new IllegalArgumentException("app.auth.refresh-cookie.same-site must be Strict, Lax or None");
        }
        if ("None".equals(sameSite) && !secure) {
            throw new IllegalArgumentException("SameSite=None requires secure=true");
        }
    }
}
```

- [ ] **Step 5: 점검 스크립트** — `scripts/smoke.sh`(실행 권한 `chmod +x`). 상태 코드·형식·본문을 모두 확인한다(200 HTML로 빗나간 응답이나 빈 본문을 통과시키지 않는다).

```bash
#!/usr/bin/env bash
# 배포된 Salad Bowl을 계정 없이 점검한다. 사용법: scripts/smoke.sh https://<Pages 주소>
# health는 Render 콜드스타트를 기다리며 최대 약 4분(요청 15초 + 대기 5초, 12회) 다시 시도한다.
set -uo pipefail

base=${1:?usage: scripts/smoke.sh https://<pages-host>}
base=${base%/}
tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT
failures=0

pass() { echo "PASS  $1"; }
fail() { echo "FAIL  $1${2:+ ($2)}"; failures=$((failures + 1)); }

# fetch NAME [curl 인자...] — 본문·헤더를 $tmp/NAME.*에 저장하고 상태 코드를 출력한다(연결 실패는 000).
fetch() {
  local name=$1
  shift
  curl -sS --max-time 15 -D "$tmp/$name.headers" -o "$tmp/$name.body" -w '%{http_code}' "$@" 2>/dev/null || echo 000
}
header() { grep -i "^$2:" "$tmp/$1.headers" 2>/dev/null | tail -1 | cut -d: -f2- | tr -d '\r' | sed 's/^ *//'; }

# expect_static NAME PATH TYPE_REGEX — 200이고 Content-Type이 맞아야 한다.
expect_static() {
  local name=$1 path=$2 type=$3 status
  status=$(fetch "$name" "$base$path")
  if [ "$status" = 200 ] && header "$name" content-type | grep -Eqi "^($type)"; then
    pass "$path"
  else
    fail "$path" "status=$status type=$(header "$name" content-type)"
  fi
}

# expect_api_error NAME STATUS [curl 인자...] — 상태가 맞고 JSON이며 {code} 본문이어야 한다(SPA HTML이 아님).
expect_api_error() {
  local name=$1 want=$2 status
  shift 2
  status=$(fetch "$name" "$@")
  if [ "$status" = "$want" ] && header "$name" content-type | grep -qi '^application/json' \
      && grep -Eq '"code":"[A-Z_]+"' "$tmp/$name.body"; then
    pass "$name -> $want json"
  else
    fail "$name" "status=$status type=$(header "$name" content-type) body=$(head -c 120 "$tmp/$name.body" 2>/dev/null)"
  fi
}

# 1) 정적 파일: 상태와 형식
expect_static index / 'text/html'
expect_static manifest /manifest.webmanifest 'application/manifest\+json|application/json'
expect_static sw /sw.js 'application/javascript|text/javascript'
expect_static registersw /registerSW.js 'application/javascript|text/javascript'
grep -q '"Salad Bowl"' "$tmp/manifest.body" && pass "manifest name" || fail "manifest name"
workbox=$(grep -Eo 'workbox-[A-Za-z0-9_-]+\.js' "$tmp/sw.body" | head -1)
if [ -n "$workbox" ]; then expect_static workbox "/$workbox" 'application/javascript|text/javascript'; else fail "workbox file" "not referenced in sw.js"; fi

# 2) 헤더: 보안 헤더, 서비스 워커 파일은 캐시하지 않음
header index x-content-type-options | grep -qi nosniff && pass "x-content-type-options" || fail "x-content-type-options"
for name in sw registersw manifest; do
  header "$name" cache-control | grep -qi 'no-cache' && pass "$name no-cache" || fail "$name no-cache" "$(header "$name" cache-control)"
done

# 3) API health(콜드스타트 대기): 200이고 본문 status가 UP
health=fail
for _ in $(seq 1 12); do
  status=$(fetch health "$base/api/actuator/health")
  if [ "$status" = 200 ] && grep -q '"status":"UP"' "$tmp/health.body"; then health=ok; break; fi
  sleep 5
done
[ "$health" = ok ] && pass "api health UP" || fail "api health" "last status=$status"

# 4) 프록시 경로와 인증: SPA가 아니라 API가 JSON 401로 답해야 한다
expect_api_error me 401 "$base/api/me"
expect_api_error api-root 401 "$base/api"
expect_api_error api-root-slash 401 "$base/api/"
# Origin을 붙여도 CORS 403이 아니라 401 JSON(프록시가 Origin을 지운다)
expect_api_error refresh-with-origin 401 -X POST -H "Origin: $base" "$base/api/auth/refresh"

echo "failures: $failures"
[ "$failures" = 0 ]
```
