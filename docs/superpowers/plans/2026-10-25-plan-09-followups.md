# Plan 09 후속 과제

Plan 09(대시보드 대분류 지출 도넛차트)의 Task별 리뷰, 브라우저 확인, 최종 리뷰에서 나왔지만 넘긴 항목이다.

## 실행 중 바뀐 결정 (기록용)
- **Task 2 구현자**: 계획은 Codex `gpt-6-astra`였지만 이전 세션에 Codex가 없어 Claude opus가 구현했다. 리뷰는 Claude sonnet이 했다.
- **강조 표시**: 강조 조각은 CSS 클래스 대신 `data-active` 속성으로 표시한다. `styles.active`가 CSS에 없어서 빌드하면 `undefined`가 됐다(Task 2 리뷰).
- **넓은 모달**: 기본 모달 폭 560px에서는 6열 거래 표의 "내용" 열이 한 글자씩 꺾였다(브라우저 1200px). `DialogFrame`에 `wide`(최대 880px)를 더했다. 시트에는 영향이 없다.
- **닫히는 동안 내용 유지**: 모달이 닫히는 동안 제목·본문이 비지 않도록, 마지막으로 연 대분류를 붙들어 둔다.
- **쿼리 키**: 거래 모달의 키를 `['summary', groupId, month, 'transactions', category]`로 바꿨다(최종 리뷰). `summary`로 시작해야 `isGroupScopedKey`와 추방·공개 전환 때의 무효화에 걸린다. 설계 6.5도 고쳤다.
- **조각 라벨(사용자 추가 요청)**: 범례와 차트를 번갈아 보지 않도록 조각마다 이름·비율을 원 둘레 바깥에 달고 짧은 지시선으로 잇는다. 처음 만든 좌우 두 열 배치는 사용자 의견으로 방사형 배치로 바꿨다. 넓은 화면은 1:1(라벨 13px), 820px 이하는 작은 도넛과 두 줄 라벨(12px, 이름 4자)로 카드 폭 안에 들어간다(375px 1:1, 320px는 약간 축소). 아래 목록은 접근 가능한 컨트롤로 그대로 둔다.
- **번들**: 홈 첫 진입 JS가 gzip 182.07 kB에서 183.61 kB(+1.54 kB)로 늘었다. 도넛 코드는 대시보드 청크에만 있고, 늘어난 것은 공용 청크 구성이 바뀐 탓으로 본다(추측, `docs/ui-library-poc.md`). 설계의 "변하지 않아야 한다"는 기준을 엄밀히는 지키지 못했다.

## 다음 과제: 차트 라이브러리 재검토 (사용자 결정, 2026-10-26)
조사 결과: [차트 라이브러리 재검토](../../chart-library-research.md) (1순위 ECharts, 2순위 AG Charts Community).
조각 라벨(이름·비율)을 직접 SVG로 배치하는 일이 커져서, 라벨·지시선 배치를 제공하는 상용·오픈소스 차트나 UI 컴포넌트를 적용하는 방향을 다시 검토한다. 설계 3장의 비교(번들 증가 gzip 50~120 kB)를 라벨 배치 품질·접근성·모바일 폭 기준으로 다시 본다.
- 지금 PR에 들어간 것: 원 둘레 방사형 라벨(8943ca0). 실제 렌더링 측정에서 작은 조각이 몰린 데이터는 선끼리 교차하거나 선이 다른 라벨을 지난다(예: 큰 조각 1개 + 작은 조각 11개, 375px에서 선-선 5건·선-글자 7건, 1200px에서 1건·2건). 글자끼리 겹치거나 잘리지는 않는다.
- 시도했지만 넣지 않은 것: 좌우 반원으로 나눠 순서를 지키며 세로로 밀어내는 타원 배치. 교차·겹침은 18가지 경우 모두 0이었지만 라벨이 위아래로 퍼져 지시선이 최장 119~209px로 길어졌다. 다듬던 중에 라이브러리 검토로 방향을 바꿔 작업 트리에서 되돌렸다(패치는 SDD 작업 폴더 `round4-uncommitted.patch`, 커밋하지 않음).
- 비교 기준으로 쓸 검사: 실제 렌더링 좌표로 선-선 교차, 선-글자, 글자-글자 겹침, 잘림, 최소 글자 크기, 최장 지시선을 1200·375·320px × 데이터 6종에서 잰다. 프로젝트 `.mcp.json`의 Playwright MCP(main에 병합됨)로 자동화할 수 있다.

## 실기기·눈으로 확인 (사용자가 직접)
- 좁은 화면(820px 이하)에서 목록 행이나 조각을 누르면 시트가 열리고, 닫기·Esc·아래로 쓸기로 닫히며, 닫힌 뒤 포커스가 누른 행으로 돌아오는지. 이번 미리보기에서는 브라우저 패널이 숨겨져 있어 시트가 그려지지 않아 확인하지 못했다(넓은 화면 모달은 열기·Esc 닫기·포커스 복귀까지 확인했다).
- VoiceOver·TalkBack: 목록 행을 "식비 32% ₩ 120,000"처럼 읽는지, 도넛은 읽지 않는지.
- 라이트 모드에서 3·4·5번 색(초록·노랑·분홍)이 흰 배경에서 구분되는지(검증기 대비 WARN, 목록 글자로 보완).
- 터치로 작은 조각을 눌렀을 때 의도한 대분류가 열리는지(작으면 목록 행을 쓴다).

## 나중에 (사소함, 리뷰에서 넘긴 것)
- API: 공용 선별 메서드가 `owners`를 인자로 받는다. 두 호출자가 같은 `sharedOwnerIds`를 쓰고 테스트가 양쪽을 확인한다.
- API: 새 엔드포인트 테스트가 같은 시각 거래의 `id` 역순과 `editable` 값을 확인하지 않는다.
- `DonutChart`가 누적합을 조각마다 다시 계산한다(O(n²), 조각이 수십 개 이하라 무해).
- 목록 색 표지의 빗금 간격이 도넛 무늬와 정확히 같지는 않다(색·방향만 같다).
- 다이얼로그 전용 스타일이 `CategoryBreakdown.module.css`에 있다.
- 거래 합계가 음수일 때 `formatWon`은 부호 없이 표시한다. 지출이 0보다 큰 대분류만 열리므로 지금은 생기지 않는다.
- 테스트 공백: 월을 바꾸면 모달이 닫히는지, 도넛 조각 클릭으로 모달이 열리는지.
- 거래 표 열 순서가 설계(내용→소분류)가 아니라 계획(소분류→내용)을 따른다.
- 거래 행 금액은 거래 화면처럼 원래 부호(지출 `-₩`, 환불 `+₩`)이고, 합계 줄은 지출을 양수로 보인다. 설계의 "환불은 음수 표시"와 어느 쪽이 맞는지 정한다.
- 표·카드 행을 눌러도 아무 일이 없는데 누를 수 있는 것처럼 보인다(설계 의도: 상세는 거래 화면에서).
- `layoutLabels`가 각도 완화와 후보 탐색 두 알고리즘을 플래그로 나눠 쓰는 긴 함수다(Task 5 리뷰 Important, 동작 결함은 없어 정리를 미룸). compact에서는 완화 결과가 거의 쓰이지 않는다. 호버마다 다시 계산한다(`useMemo` 없음).
- 라벨 폭은 글자 수 어림(한글 1em, 그 외 0.6em)이라 영문 대문자처럼 넓은 이름은 잘릴 수 있다. 두 줄 라벨의 둘째 줄 앞 공백이 정렬을 조금 민다.
- 라벨 테스트의 "viewBox 안" 검사는 viewBox를 같은 상자로 계산해 동어반복에 가깝다. 값 0·합계 0 입력 테스트가 없다.
- 넓은 모달에서 일시 열이 일부 행에서 두 줄로 꺾인다.
