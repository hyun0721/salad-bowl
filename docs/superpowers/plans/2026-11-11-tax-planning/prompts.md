# 단계별 시작 프롬프트

각 블록은 해당 단계만 실행하는 시작 프롬프트다. 현재 worktree를 지정한 채 사용한다.
공통 자료: `docs/superpowers/plans/2026-11-11-tax-planning/README.md` 및 `reference.md`.

## 1. PRD 작성

```text
샐러드볼 개인 소득공제 기능의 PRD를 작성해줘.
먼저 AGENTS.md, docs/agent-guidelines.md와 salad-bowl-workflow 스킬,
docs/superpowers/plans/2026-11-11-tax-planning/{README,reference}.md를 읽어줘.
현재 브랜치와 등록된 worktree를 확인하고, 기본 checkout에서는 수정하지 마.

회원별 개인 자료 등록, 관리자의 연도별 세법 갱신, 그룹 활용의 후속 확장은 사용자 확정사항이야.
나머지 제안은 확정으로 간주하지 말고 근거와 함께 검토해줘.
현재 코드의 인증·그룹 의존·메뉴·캐시·관리자 역할 유무를 확인해줘.
노션 원문은 필요할 때 재조회하되 개인 금액과 원자료를 저장소에 넣지 마.
지원 귀속연도의 공식 법령·시행령·부칙을 검증하고 출처와 적용일을 기록해줘.

PRD에는 목표·대상·범위, 요구사항 ID, 역할별 권한, 사용자 흐름, 메뉴,
논리 데이터와 입력 검증, 조회 항목·비율 분모, 계산·추천 정책, 세법 운영,
오류·미완료·삭제·재계산 상태, 수용기준, 미결정 사항을 포함해줘.
reference.md의 D01~D10에 추천안을 작성하고 결정이 필요한 사항을 구체적으로 제시해줘.
산출물은 docs/superpowers/specs/2026-11-11-tax-prd.md에 작성하고 준비 README 상태를 갱신해줘.
이번 단계는 PRD 검토본까지야. 와이어프레임·앱 구현은 시작하지 마.
문서 링크와 요구사항 누락을 확인하고 변경을 커밋해줘. push·PR·병합은 하지 마.
```

## 2. 와이어프레임 작성

```text
샐러드볼 소득공제 기능의 와이어프레임을 작성해줘.
AGENTS.md, 공통 규칙, 준비 패키지와 작성된 PRD를 먼저 읽어줘.
PRD의 사용자 검토 상태를 확인하고 미결정 사항을 확정된 것처럼 구현하지 마.
작업 가능한 worktree인지 확인하고 기존 AppLayout·디자인 토큰·common 부품을 조사해줘.

회원의 입력자료 / 분석·지출계획과 관리자 세법 관리 화면을 구성해줘.
각 화면을 PRD 요구사항 ID에 연결하고 메뉴·탭·본문 영역·버튼을 구분해줘.
375px 모바일과 데스크톱에서 입력표, 금액 단위, 비율 분모, 기준일,
회차 생성·복사·수정·삭제, 예산 입력·추천 비교, 세법 초안·적용·버전 흐름을 보여줘.
그룹 미가입, 데이터 없음, 부분 입력, 잘못된 값, 기준일 불일치,
세법 미등록·새 버전 존재, 권한 없음·통신 오류 상태도 포함해줘.
합성 데이터만 사용하고 원문의 개인 금액은 사용하지 마.

우선 로컬에서 검토 가능한 화면 산출물과 화면 설명서를 만들고,
docs/superpowers/specs/2026-11-11-tax-wireframes.md에 연결해줘.
Figma가 필요하면 대상과 산출물 형식을 확인한 뒤 해당 스킬을 사용해줘.
시각 검증과 접근성 검토 결과를 남기고 준비 README를 갱신해줘.
이번 단계는 와이어프레임 검토본까지야. 운영 앱·API·DB는 구현하지 마.
검토 가능한 산출물을 커밋하고 push·PR·병합은 하지 마.
```

## 3. 개발착수

```text
샐러드볼 소득공제 기능의 승인된 PRD와 와이어프레임을 기준으로 개발을 시작해줘.
AGENTS.md, 공통 규칙, salad-bowl-workflow 스킬, docs/development.md,
준비 패키지, PRD, 와이어프레임을 읽고 승인 상태·남은 결정을 확인해줘.
미결정 사항은 근거와 추천안을 구체화해 확인하고 관련 구현은 확정 후 진행해줘.
현재 main과 기획 기준 커밋 차이를 점검하고 문서가 누락되지 않은 작업 브랜치에서 진행해줘.

먼저 docs/superpowers/plans/2026-11-11-tax-implementation.md에
요구사항 ID별 작업·의존성·변경 파일·migration·API·UI·테스트·PR 분할을 작성해줘.
데이터 소유권, 서비스 관리자 권한, 세법 적용 버전, 금액 계산,
개인 메뉴의 그룹 독립성, 로그아웃 캐시 제거를 반드시 포함해줘.
공식 근거로 계산 테스트 기대값을 작성하고 실제 개인 데이터는 사용하지 마.
새 의존성·범용 수식 엔진은 필요성이 확인되지 않으면 추가하지 마.

계획이 기존 승인 범위와 일치하면 첫 구현 단위부터 구현·검증해줘.
웹 변경은 typecheck/test/lint/build, API 변경은 Gradle test,
해당 시 memoryTest와 공유 검증 스택을 저장소 규칙대로 수행해줘.
375px 화면 검증과 권한·계산 경계 테스트를 포함하고 미실행 검증을 명시해줘.
독립 리뷰가 필요한 변경은 저장소 리뷰 규칙에 따라 별도 담당자의 리뷰를 준비해줘.
진행 상태와 다음 작업을 구현 계획·준비 README에 갱신하고 커밋해줘.
외부 게시·push·PR·병합은 별도 요청 범위에 따라 진행해줘.
```
