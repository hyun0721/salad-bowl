# 소득공제 기능 — 요구사항 및 참고자료

## 사용자 확정사항

- 회원은 본인의 자료를 개별 등록한다. 그룹 단위 활용은 후속 고도화로 둔다.
- 연도별 세법은 관리자가 매년 직접 갱신한다.
- 입력자료 조회에서 소비구분과 금액을 보여준다.
- 분석자료 조회에서 소비구분별 비율과 추천 지출계획을 보여준다.
- PRD → 와이어프레임 → 개발착수 순서로 진행할 준비자료를 만든다.

## 대화에서 제안한 안 — PRD에서 검토·확정 필요

- 회원 메뉴: 소득공제 > 입력자료 / 분석·지출계획. 관리자 메뉴: 연도별 세법 관리.
- 하위 세부항목은 별도 메뉴가 아니라 화면 영역 또는 버튼이다.
- 본인만 조회·수정·삭제하고 그룹 공개 설정과 독립적으로 취급한다.
- 개인 누계자료를 수동 등록하며 기존 가계부 자동 합산은 후속으로 둔다.
- 회차별 누계 스냅샷을 만들고 이전 회차 복사를 제공한다. 회차 간 누계를 더하지 않는다.
- 소득공제액을 주 결과로 제공하고 실제 환급액·카드 혜택 최적화·부양가족 사용액 합산은 첫 범위에서 제외한다.
- 동일 예산·소비구분을 고정하고 결제수단 변경에 따른 공제 차이를 비교한다.
- 공제한도까지 필요한 소비액은 참고치이며 추가 소비 권유로 표현하지 않는다.

## 데이터 후보

| 개념 | 주요 항목 | 검토할 제약 |
|---|---|---|
| 세법 기준 | 귀속연도, 버전, 공제율, 기준비율, 급여구간, 기본·추가한도, 자녀 등 조건, 적용기간, 근거, 상태 | 초안→적용, 적용본 불변·새 버전, 계산 알고리즘 버전 연결 |
| 분석회차 | 소유 회원, 귀속연도, 회차명, 총급여, 근로기간, 자녀 등 요건, 세법 버전, 지출계획 | 개인 소유, 연도 일치, 과거 결과 재현 |
| 입력자료 | 회차, 자료명, 출처, 누계기간, 메모 | 자료별 포함범위·중복 출처·기준일 불일치 |
| 소비금액 | 입력자료, 결제수단, 소비구분, 공제대상액 | 원 단위, 0과 미입력 구별, 조합 중복 금지 |

위는 논리적 개념이다. 물리 테이블 4개로 고정하지 않는다. 세법 구간·근로기간·지출계획 상세의 자식 구조는 PRD와 개발 설계에서 정한다.
결제수단: 신용 / 체크·직불 / 소득공제용 현금영수증.
소비구분: 일반 / 전통시장 / 대중교통 / 문화체육. 기존 생활 카테고리와 구별한다.
출처: 카드사 / 홈택스 / 기타. 출처는 결제수단이 아니다.
세법 변경으로 새로운 유형·순서가 생기면 코드 변경이 필요할 수 있다. 임의 수식 실행 기능은 제안하지 않는다.

## 사용자 입력과 조회 후보

입력: 귀속연도, 예상 총급여, 근로기간, 한도 상향 대상 자녀 등 조건, 자료명·출처·누계기간,
결제수단×소비구분 공제대상액, 선택 메모. 추천 이용 시 남은 예산과 공제대상 예상액,
변경 가능한 지출, 고정 결제수단·소비구분별 예상액을 받는다.
예산 항목 간 합계·포함관계를 명확히 정의해야 한다.

입력자료 화면: 회차 목록·복사, 기본정보, 자료 목록·상세·수정·삭제, 통합 합계, 미완료 상태.
분석 화면: 기준금액 달성, 공제액, 기본·추가한도, 결제수단 비율, 소비구분 비율,
동일 예산 시나리오, 추천 배분·이유·가정, 적용 세법·자료 기준일.
사용액 비율의 분모는 전체 입력 공제대상액이다. 공제율·한도 사용률과 혼동하지 않는다.
0원은 빈 차트 상태로 표시하고 부분 입력은 완성된 분석처럼 표시하지 않는다.

## 노션에서 확인한 사실과 한계

원문: [2026 지출·카드 소득공제 분석](https://app.notion.com/p/donghyun721/2026-3f56dfc76d648138bb4ddae3514e8b22)
대화에서 본문, Raw Data 3건, 분석회차 1건을 조회했다. 원본 확인서와 실제 Formula 코드·실행값 전체를 검증하지 않았다.
이번 준비 작업에서는 재조회하지 않았으며 아래는 앞선 조사 요약이다.
실제 급여·소비금액·개인 원자료는 이 저장소에 복제하지 않는다.

- 카드사·홈택스별 누계자료를 분석회차에 연결하는 구조는 재사용할 수 있다.
- 문서의 단순식은 신용카드에서 차감하지 못한 최저사용금액을 다른 사용분에 반영하지 못할 수 있다.
- 기본한도만 적용하므로 추가한도와 자녀 등 한도 상향 확인이 필요하다.
- 급여 조건 미충족 문화체육 사용분을 모두 일반 신용카드로 돌리면 원래 체크·현금 결제를 잃는다.
- 특별 사용분이 일반 합계에 포함되는 자료라면 중복 집계될 수 있다.
- 잔여한도÷공제율은 모든 상황에서 유효한 추천 계획이 아니다.

## 최신 main에서 확인한 통합 지점

기준 커밋은 README에 기록했다. 다음 단계 시작 시 최신 코드와 다시 대조한다.

- `apps/api/src/main/java/com/saladbowl/api/transaction/LedgerTransaction.java`: 회원 ownerId, 문자열 paymentMethod, 생활 카테고리, 금액. 세법 분류를 직접 제공하지 않는다.
- `apps/api/src/main/java/com/saladbowl/api/user/User.java`: 서비스 관리자 역할 필드가 없다. 그룹 관리자와 서비스 관리자를 혼동하지 않는다.
- `apps/web/src/app/AppRoutes.tsx`: 로그인 후 화면이 GroupProvider 아래에 있다. 그룹 미가입 회원의 개인 메뉴 접근을 검토한다.
- `apps/web/src/app/AppLayout.tsx`, `apps/web/src/common/`: 메뉴·기존 UI 부품 재사용 확인 지점.
- `apps/api/src/main/resources/db/migration/`: Flyway 새 migration으로 스키마 추가.
- `apps/api/src/main/java/com/saladbowl/api/auth/SecurityConfig.java`: 인증·관리자 API 권한 검토 지점.
- `apps/web/src/app/ClearCacheOnSignOut.tsx`: 로그아웃·회원 전환 시 개인 데이터 캐시 제거 검토 지점.

## 수용기준·검증의 씨앗

- 회원 A는 B의 회차·자료·계획을 ID 변경으로 읽거나 수정·삭제할 수 없다.
- 그룹 미가입·탈퇴·그룹 변경이 개인 데이터 접근을 막거나 공개하지 않는다.
- 일반 회원은 세법 기준을 수정·적용하지 못한다.
- 기준금액 미달·동일·초과, 급여구간 경계, 자녀 등 조건, 기본·추가한도 포화를 계산한다.
- 문화체육 우대 미적용 시 원래 결제수단으로 계산하며 중복 집계하지 않는다.
- 동일 예산에서 추천 전후 합계는 같고, 공제상 차이가 없으면 명확히 표시한다.
- 회차 복사·누계 갱신·세법 재계산·로그아웃 캐시·동시 수정·삭제를 검증한다.
- 테스트 기대값은 계산기 구현을 복제하지 말고 공식 산식과 합성 사례로 독립 산출한다.
