# Plan 07b 후속 과제

Plan 07b(대화상자·알림·탭)의 Task별 리뷰(Sonnet 구현 ↔ Opus 리뷰), 브라우저 확인, 최종 리뷰(Opus + Codex)에서 나왔지만 넘긴 항목이다.

## 실행 중 바뀐 결정 (기록용)
- **Codex 협업**: Codex가 사용량 한도에 걸려 있던 동안 Task 1~5는 Claude(Sonnet 구현, Opus 리뷰)로 진행했다. 최종 브랜치 리뷰는 Opus와 Codex가 함께 했고 둘 다 머지 가능으로 판단했다.
- **시트 배경**: 계획대로 모달용 `.backdrop`을 시트에도 썼더니 `z-index`가 시트 내용을 덮어 탭을 막을 수 있었다(계획 실수). 시트 전용 `.sheetBackdrop`(배경색만)으로 고쳤다.
- **모바일 버튼 높이**: 브라우저 확인에서 `ui.button`이 좁은 화면에서도 40px인 것을 찾았다. 820px 이하에서 44px로 올렸다(앱 전체 버튼에 적용).
- **SegmentedControl**: RAC `ToggleButtonGroup`이 이미 선택된 버튼을 다시 누르면 같은 값을 다시 알린다. 같은 값이면 무시한다.
- **알림 영역**: 스펙의 `AppLayout`이 아니라 `App.tsx`에 둔다(로그인 화면에서도 쓸 수 있게). RAC Toast는 1.22.1에서 `UNSTABLE_` API라 `common/Toast.tsx` 한 파일에서만 쓴다.
- **번들**: JS gzip 216.87 kB → 223.63 kB(`docs/ui-library-poc.md`).

## 브라우저에서 확인할 것
- 거래를 삭제하면 패널이 닫히면서 포커스가 `body`로 간다(트리거가 사라진다). 멤버 내보내기도 같다. 이전 제자리 확인 방식도 같았다. 삭제 뒤 거래 목록이나 제목으로 포커스를 옮길지 정한다.
- 시트 배경(어둡게 깔리는 정도)이 옅다. RAC 시트가 배경 투명도를 시트가 올라온 정도에 맞추는 기본 동작이다(계정 시트도 같다). 더 진하게 할지 실기기에서 본다.

## 다음 단계에 더할 것
- `DialogFrame`과 `ResponsiveOverlay`의 `useOverlayMode`가 "열린 동안 모양 고정" 로직을 따로 갖고 있다. 하나로 합치고, 닫힘 애니메이션이 끝날 때까지 고정을 유지한다(지금은 열린 채 화면을 돌린 뒤 닫으면 닫힘 애니메이션 없이 사라진다).
- 모바일 시트는 바깥을 누르면 닫힌다. 그룹 이름이나 월 삭제 확인 문구를 입력하던 중 실수로 바깥을 누르면 입력이 사라진다. 입력이 있는 대화상자는 막을지 정한다.
- 범위가 "내 거래"로 되돌아갈 때 열려 있던 그룹 거래 상세 패널(`selectedId`)이 그대로 남는다.

## 나중에 (사소함)
- `Dialog.test.tsx`의 Tab 테스트가 순서(되돌아오기)는 보지 않는다.
- `TransactionPanel.test.tsx` 삭제 실패 문구, `GroupsAdmin.test.tsx` 복사 실패 문구를 대화상자·영역 안으로 좁혀 찾지 않는다.
- 확인 대화상자 처리 중 테스트가 바깥 누르기 막힘을 보지 않는다.
- 공개 스위치 테스트가 붙잡은 요청을 `finally`에서 풀지 않는다(실패할 때만 문제).
- `LeaveGroup`에 자식 하나만 감싼 `div`가 남아 있다. 확인 트리거가 거래 패널의 `form` 안에 있다(RAC Button 기본 `type="button"`이라 지금은 안전).
- 좁은 화면 로그인 페이지에서는 하단 탭 바가 없는데도 알림 영역이 56px 위에 뜬다(로그인 화면에서 아직 알림을 쓰지 않는다).
- 로그인 안내·오류 문단이 탭 밖으로 나오면서 제출 버튼과의 간격이 6px 넓어졌다.
