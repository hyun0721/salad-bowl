# 소분류 대분류 목록 초기 조회 분석과 조치

## 현상과 확인 범위

- 배포 사이트에서 소분류 기능의 대분류 목록이 처음에 비었으며, 이후 사용자가 정상 동작을 확인했다.
- PR #44가 병합된 `e2f77be`를 새 워크트리에서 검토했다.
- 제품 코드를 바꾸기 전 임시 테스트로 초기 응답 지연 중 선택창 열기를 데스크톱·모바일에서 확인했다. 두 경우 모두 응답 후 목록과 선택이 정상 반영됐다. API 404일 때는 안내 항목만 있는 빈 선택창이 열리는 현상을 재현했다. 진단 3개 통과 후 임시 파일은 제거했다.
- 로그인된 실제 사용자의 실패 요청·응답은 확보하지 못했다. 최초 진단 시 브라우저 제어가 비활성화되어 임시 테스트로 확인했다. 이후 Playwright를 연결해 아래의 모바일 미리보기를 검증했다.

웹에 새 기능이 먼저 노출되고 API가 약 3분 47초 늦게 반영됐다. 대분류 목록은 새 `/groups/{groupId}/summary/subcategories` 응답에서 만들어지므로, 이 구간에 새 API가 없는 서버로 요청했다면 목록도 비게 된다. 이후 정상 동작했다는 사용자 확인과 일치해 **배포 시차가 가장 유력한 원인**이다. 당시 실제 404 응답을 확보하지 못했으므로 확정 원인으로 단정하지 않는다.

증상을 악화한 UI 문제는 확인했다. 로딩·실패·정상 빈 결과 모두 빈 선택창을 열 수 있었다. 전역 쿼리 설정은 4xx를 재시도하지 않고 창 포커스 복귀 때도 재조회하지 않으므로, 최초 실패 후 서버 배포가 끝나도 수동 재시도나 새로고침 전까지 오류 상태가 남을 수 있다.

## 이번 조치

1. 목록 조회가 성공하고 선택 가능한 대분류가 있을 때만 선택창을 표시한다.
2. 조회 중에는 ‘대분류 목록을 불러오는 중’, 실패하면 실패 안내와 기존 재시도 버튼, 성공했지만 데이터가 없으면 ‘최근 6개월에 공개된 지출이 없음’을 구분한다.
3. 대분류에 ‘필수’를 표시하고 모바일(820px 이하)에서는 제목 다음 줄의 전체 너비로 배치한다. 데스크톱은 기존 제목 우측 배치를 유지한다.
4. 초기 응답 지연, 모바일 선택, 404·503 이후 재시도 성공, 정상 빈 결과 회귀 테스트를 추가한다. 기존 단일 선택·월 변경·환불·증감 강조 검증을 유지한다.

그룹 접근 거부도 404를 사용하므로, 모든 404에 자동 재시도를 추가하거나 전역 그룹 쿼리 정책을 변경하지 않는다. 새 대분류 목록 API나 개인용 `/me/categories`의 대체 사용도 추가하지 않는다. 개인 후보와 그룹 공개 거래의 범위가 다르기 때문이다.

## 배포 및 검증

- 새 API와 이를 사용하는 웹은 서버를 먼저 반영하는 두 단계 배포로 진행한다. 서버의 해당 커밋 배포 완료와 테스트 계정의 실제 엔드포인트 성공을 확인한 뒤 웹 변경을 공개한다. `/actuator/health` 성공만으로 새 API 반영을 판단하지 않는다.
- 서버·웹을 함께 공개해야 하는 변경은 양쪽 배포 완료 후 기능 확인을 마친다. 시차 중 실패한 화면은 기존 재시도 버튼 또는 새로고침으로 복구되는지 확인한다.
- 웹 최종 검증: `npm run typecheck && npm test && npm run lint && npm run build` 통과. 전체 56개 테스트 파일·378개 테스트 통과.
- API·집계·공개 범위·배포 자동화 설정은 이번 수정에 포함하지 않는다. Playwright의 390×844 모바일 화면에서 제목 아래 전체 너비 선택창과 대분류 선택·증감 강조·분포 표시를 확인했다. 표의 소분류명이 글자 단위로 줄바꿈되지 않도록 수정했다. 미리보기는 가짜 API 데이터이며, 실제 배포 API와의 첫 조회는 별도 확인이 필요하다.
