# UI 표준

Salad Bowl 앱 전체의 화면 정책이며, 새 화면과 수정하는 화면에 적용한다.
2026-11-13 그룹 관리 개선에서 합의한 배치·문구·도움말 원칙을 정리했다.
2026-11-05 모바일 기준안과 2026-11-23 디자인 시스템 정비를 근거로 더했다.

**정보는 왼쪽, 조작은 오른쪽에 두고, 기본 화면에는 판단에 필요한 내용만 보여준다.**
모바일 PWA에서 터치로 사용할 수 있어야 하며, 넓은 화면에서도 같은 배치 원칙을 따른다.

| [화면 일관성 설계](superpowers/specs/2026-10-30-design-consistency-design.md) | 제목·추가 버튼·금액 표기의 설계 이력 |

과거 설계의 당시 화면·수치가 현재 구현을 뜻하지는 않는다. 공통 UI 방향은 이 문서,
색·크기 등의 실제 값은 `apps/web/src/styles/tokens.css`, 동작은 현재 공용 부품과
해당 기능의 설계를 함께 확인한다. 기준을 바꾸면 이 문서도 함께 갱신한다.

## 배치

| 요소 | 기준 | 예시 |
|---|---|---|
| 화면·섹션 제목과 실행 버튼 | 제목은 좌측, 해당 버튼은 같은 영역의 우측 끝 | 내 그룹 / 추가, 초대 링크 / 초대 링크 만들기 |
| 입력과 실행 버튼 | 입력 영역은 좌측에서 남는 폭을 사용하고, 버튼은 우측 | 새 이름 입력 / 이름 바꾸기, 초대 주소 / 링크 복사 |
| 설정 행 | 제목·설명은 좌측, 토글 등 설정형 입력은 우측 | 내 거래 그룹 공개 / 토글 |
| 목록 행 | 이름·상태는 좌측에 쌓고, 행별 버튼은 우측 | 멤버 정보 / 내보내기, 차단 정보 / 차단 해제 |
| 독립 실행 버튼 | 소속 섹션의 우측 끝 | 그룹 나가기, 만들기 |
| 확인창의 버튼 묶음 | 확인·실행을 우측, 취소를 그 왼쪽 | 취소 / 나가기 확인 |

- 우측은 화면 전체가 아닌 **그 조작이 속한 카드·섹션·행의 오른쪽 끝**이다.
- 도움말 `?`는 대상 제목 옆에 둔다. 실행 버튼과 구별하고, 토글을 누르는 영역에 넣지 않는다.
- 일반 폼 입력 전체를 우측으로 몰지 않는다. 좌측 입력과 우측 실행 버튼의 관계를 유지한다.
- 긴 이름·설명은 좌측에서 줄바꿈한다. 우측 버튼·토글을 화면 밖으로 밀거나 서로 겹치게 하지 않는다.
- 공간이 부족해 실행 버튼을 다음 줄에 놓아야 해도 우측 정렬을 유지한다.
- 내비게이션·탭·차트 등은 각 공용 부품의 구조를 따른다. 이 정렬 규칙은 제목·설정·폼·목록의 조작에 적용한다.

```text
제목 (?)                         [실행]

입력 라벨
[입력 영역                    ] [저장]

설정 제목 (?)                    [토글]
짧은 설명

멤버 이름                     [내보내기]
역할 · 공개 상태 · 합류 일시
```

## 버튼과 조작

넓은 화면에서 같은 줄의 독립 버튼과 입력은 `--control-height`로 높이를 맞춘다. 사이드바 메뉴와 목록 행은 `--row-height`를 따른다.

| 역할 | 기준 |
|---|---|
| 일반 버튼 | 좁은 화면 높이 `--touch-target` 이상, 좌우 여백 `--space-5`, 최소 폭 `--touch-target` |
| 주 실행 버튼 | 화면·창에서 하나. 브랜드 채움(`ui.primary`), 좁은 화면 높이 `--control-height-primary`(`ui.cta`). 브랜드 채움은 주 실행에만 쓴다 |
| 아이콘 버튼 | 좁은 화면 `--touch-target` 정사각형. 보이는 글자가 없으면 접근성 이름을 붙인다 |
| 자주 반복하는 동작 | 아이콘과 글자를 함께 쓴다. 아이콘만 쓰는 것은 편집·삭제·닫기처럼 의미가 굳은 동작에 한한다 |
| 위험 동작 | 목록·카드에서는 외곽선(`ui.danger`), 채움(`ui.dangerFill`)은 확인창의 확정 버튼에만 |
| 닫기 | 창·시트의 오른쪽 위 X, 누름 영역 `--touch-target` |
| 폼 푸터 | 닫기와 겹치는 취소는 두지 않고 주 실행을 전체 폭으로. 초기화 같은 보조 동작이 있으면 보조 1 : 주 2(`ui.confirmActions`) |

### 선택 컨트롤

- 여러 값 중 하나를 고르는 컨트롤은 회색 트랙 위 흰 조각 한 가지 모양을 쓴다. 공통 스타일은 `common/Segmented.module.css`이며 `SegmentedControl`, `Tabs`, 대시보드 메뉴, 차트 보기 전환, 거래 종류 필터가 이를 가져다 쓴다.
- 넓은 화면의 선택 조각은 `--segment-height`, 페이지 탭은 `--tab-height`를 쓴다. 카드 제목 옆에 단독으로 놓이는 차트 보기 전환은 38px 예외다. 선택은 굵은 글자와 `--shadow-raised`, 포커스는 `--brand` 외곽선으로 표시한다.
- 새 선택 컨트롤을 만들 때 스타일을 복제하지 않고 이 공통 스타일을 `composes`로 가져다 쓴다.
- `composes: segment`를 쓰는 모듈은 `min-height`·`padding`을 직접 쓰지 않고 아래 변수로 바꾼다. production 빌드는 composes한 규칙을 청크마다 복제하므로, 직접 쓴 속성은 나중 청크에서 덮어써진다.

| 바꿀 값 | 설정할 변수 |
|---|---|
| 조각 최소 높이 | `--segment-min-height` (기본 `--segment-height`) |
| 조각 여백 | `--segment-padding` |
| 좁은 화면 좌우 여백 | `--segment-padding-inline` |

- 즉시 반영되는 설정은 Switch, 저장 시 반영되는 선택은 Checkbox라는 기존 구분은 그대로다.

## 문구와 정보의 우선순위

### 카드 제목

그룹 관리는 `내 그룹` → `그룹 정보` → `멤버 관리`로 나눈다.
`그룹 정보`에는 그룹 이름과 내 공개 설정, `멤버 관리`에는 목록·초대·차단·나가기를 둔다.
카드 제목은 기능을 나타내는 고정 문구로 쓰고, 그룹 이름은 본문에 표시한다.
이름 변경 입력의 라벨은 `그룹 이름`이며, 일반 멤버에게는 읽기 전용 텍스트로 제공한다.

글자 크기는 [앱 공통 글자 체계](#앱-공통-글자-체계)를 따른다. 글자와 함께 행간·항목 간격을 확보한다.

### 설명과 상태 문구

- 제목은 기능을 식별할 수 있게 짧게 쓴다. 버튼은 누르면 일어나는 행동을 쓴다.
- 기본 설명은 가능하면 짧은 한 문장으로 쓴다. 폭이 좁다는 이유로 필요한 내용을 잘라 숨기지는 않는다.
- 제목·버튼만으로 이해되는 동작에는 설명을 덧붙이지 않는다.
- 보충 규칙·배경·상세 절차는 도움말로 옮긴다.
- 현재 상태·실행 불가 이유·오류와 해결 방법은 화면에 직접 표시한다.
- 나가기·내보내기·삭제의 결과는 확인창에 명시한다. 중요한 결과를 도움말에만 넣지 않는다.

| 사례 | 기본 화면 | 도움말 또는 확인창 |
|---|---|---|
| 내 거래 그룹 공개 | 이 그룹에 내 거래를 공유해요. | 끄면 그룹 대시보드·그룹 거래에서 제외됨, 숨긴 거래는 공개해도 보이지 않음 |
| 초대 링크 | 생성·복사 버튼, 생성 후 실제 만료일 | 7일간 유효, 로그인·가입 후 합류 |
| 차단 목록 | 목록 또는 차단한 사람이 없어요. | 차단 중에는 재합류 불가, 해제 후 재초대 가능 |
| 그룹 정원 초과 | 정원과 새로 초대할 수 없는 이유 | 기본 화면에서 안내 |
| 복사·저장 실패 | 오류와 재시도·직접 복사 등 다음 행동 | 기본 화면에서 안내 |
| 멤버 내보내기 | 내보내기 버튼 | 확인창에 차단과 재합류 제한 명시 |

### 문구 어미

| 구분 | 어미 | 예 |
|---|---|---|
| 서술·상태·확인 문장 | 해요체 (`~해요`, `~예요/이에요`, `~했어요`, `~할 수 없어요`, `~할까요?`) | 목록 또는 차단한 사람이 없어요. |
| 입력값 검증·바로 고칠 지시 | `~하세요` | 0원 이상 입력하세요 / 대분류를 하나 이상 선택하세요. |
| 오류 뒤 다음 행동 부탁 | `~해 주세요` | 잠시 후 다시 시도해 주세요. |
| 고르는 동작의 동사 | `선택` (`고르세요`는 쓰지 않는다) | 분류를 선택 |
| 로더 캐릭터 문구 | 해요체 (`SaladBowlLoader`, `SaladBowlOverlay`에만) | 신선한 재료 찾는 중이에요 |

## 도움말

- PWA에서는 마우스 호버나 HTML `title`에만 의존하지 않는다. `?`를 눌러 여는 팝오버를 쓴다.
- 다시 누르기·바깥 터치·닫기 버튼·Esc로 닫을 수 있게 한다.
- 키보드로 열고 읽고 닫을 수 있어야 한다. 닫을 때 포커스가 사라지지 않도록 복귀를 확인한다.
- 버튼과 도움말에는 `내 거래 그룹 공개 도움말`처럼 대상을 구별할 수 있는 접근성 이름을 붙인다.
- 도움말을 열거나 닫아도 토글 값이 바뀌거나 저장 요청이 발생하지 않아야 한다.
- 팝오버는 화면 안에서 줄바꿈하고, 높이가 부족하면 내부에서 스크롤할 수 있게 한다.
- 짧은 보충 설명은 팝오버로 제공한다. 입력·선택·확인이 필요한 흐름은 기존 대화상자·시트를 쓴다.

## 피드백과 상태 표시

| 상황 | 수단 |
|---|---|
| 저장·삭제·복사 같은 동작의 성공 | `Toast`. 화면을 막지 않고 사라진다 |
| 입력 오류 | 해당 입력 아래 오류 문구(`TextField`의 오류 상태). 토스트로만 알리지 않는다 |
| 불러오기·저장 실패 | 해당 영역의 `ui.alert`와 재시도 같은 다음 행동 |
| 되돌릴 수 없는 동작(삭제·내보내기·나가기) | `ConfirmDialog`에 결과와 복구 가능 여부를 쓴다 |
| 처음 불러오는 영역 | 모양이 정해진 영역은 `Skeleton`, 화면 전체 대기는 `SaladBowlLoader`/`SaladBowlOverlay` |
| 빈 상태 | `ui.status`로 비어 있는 이유와 다음 행동을 한 문장으로 쓴다 |

## PWA와 접근성

- 좁은 화면 기준은 기존 `(max-width: 820px)`와 `common/useMediaQuery.ts`를 따른다.
- 모바일 독립 실행 버튼·아이콘 버튼·도움말·토글의 누르는 영역은 최소 44×44px로 확보한다.
  아이콘이나 토글 그림 자체를 44px로 키울 필요는 없다.
  차트 범례·기간 선택·분류 탭처럼 조합된 컨트롤은 아래 대시보드의 유형별 기존 높이를 따른다.
- 기존 `AppLayout`의 상하좌우 안전 영역과 하단 탭 바 여백을 유지한다.
  팝오버와 확인창이 화면 밖으로 나가거나 조작부를 가리지 않게 확인한다.
- 긴 그룹명·멤버명, 글자 확대 시 줄바꿈과 행간을 확인한다. 고정 높이로 내용이 잘리지 않게 한다.
- 입력과 토글은 보이는 라벨과 연결한다. 아이콘은 장식으로 처리하고 버튼 이름을 별도로 제공한다.
- 포커스·선택·비활성·저장 중·오류 상태를 유지한다. 저장 중 중복 실행을 막고 실패 시 재시도할 수 있게 한다.
- 즉시 반영되는 설정은 Switch, 저장 시 반영되는 선택은 Checkbox를 쓰는 기존 구분을 따른다.

## 대화상자·시트·선택 팝오버

그룹 생성·내보내기 확인·업로드·거래 편집·공통 설정 등은 [앱 공통 글자 체계](#앱-공통-글자-체계)를 따른다.
넓은 화면의 모달과 모바일 시트 모두 적용하며, 선택 팝오버의 항목도 본문 크기를 따른다.

- `Overlay.module.css`의 공용 `typography`를 `DialogFrame`, `BottomSheet`, `ResponsiveOverlay`에서 사용한다.
- 기본 행간은 1.5로 두고 창 본문과 폼의 간격도 함께 확보한다.
- 모바일 입력칸은 `--text-input` 글자와 `--touch-target` 터치 영역, 기존 안전 영역·스크롤·포커스·닫기 동작을 유지한다.
- 창 안의 본문이 길면 스크롤할 수 있게 한다.

## 대시보드

- 카드 제목·범례·본문·금액·비율·보조 정보는 [앱 공통 글자 체계](#앱-공통-글자-체계)를 따른다.
- 카드·컴포넌트 사이의 간격은 기존 토큰과 크기를 유지한다.
- 차트 내부 글자는 기존 축·라벨·가운데 금액 맞춤 규칙을 유지한다.
  바깥 범례의 긴 이름은 줄바꿈해 제공한다.
- 제목 좌측·차트/목록 전환 우측, 오류 좌측·재시도 우측, 목록 펼치기·접기 우측을 유지한다.
- 높이는 조작 유형별로 구분한다. 기존 모바일 추이 범례 버튼은 36px, 기간 선택·분류 탭의
  항목은 40px를 유지한다. 목록 행·달력 날짜는 `--row-height`, 좁은 화면에서는 `--touch-target`이고
  선택 목록 항목은 넓은 화면 `--row-height`, 좁은 화면 `--control-height-primary`이다.
  독립 실행·입력·아이콘 버튼의 높이를 범례·선택 컴포넌트에 일괄 적용하지 않는다.
- 긴 기간 표의 가로 스크롤은 표 내부에서만 허용하고, 페이지 전체는 가로로 넘치지 않게 한다.
- 공용 부품의 다른 사용처를 함께 바꾸지 않는다.

## 거래 목록의 모바일 카드

- 거래명·금액 아래에서 좌측은 분류 → 태그·메모, 우측은 일시 → 멤버명으로 나눈다. 메모 길이가 우측 멤버명을 아래로 밀지 않게 한다.
- 메모는 태그를 제외한 내용만 `메모` 라벨과 함께 표시한다. 태그를 먼저, 메모를 그 뒤에 같은 줄로 표시하고 폭이 부족하면 줄바꿈한다. 태그와 메모가 모두 없으면 해당 줄을 만들지 않는다.
- 분류·메모·긴 멤버명은 줄바꿈한다. 태그는 메모에 중복하지 않고 기존 검색 동작을 유지한다.
- 숨김·수정됨은 별도 상태 줄에 둔다. 그룹 거래의 멤버명은 날짜 바로 아래에 우측 정렬한다.
- 클릭 가능한 태그와 조회 전용 태그는 같은 칩 모양과 [앱 공통 글자 체계](#앱-공통-글자-체계)의 보조 글자 토큰을 쓴다. 조회 전용 태그에 검색 동작이나 버튼 의미를 추가하지 않는다.
- 거래 목록과 대시보드 분류별 거래 목록의 스크롤바는 이동 중에 표시하고, 마지막 이동 후 600ms가 지나면 숨긴다. 스크롤바 자리를 확보해 표시 여부로 내용 폭이 바뀌지 않게 한다.
- 대시보드의 분류별 거래 창도 같은 카드를 쓴다. 창 제목에 있는 대분류는 카드에서 반복하지 않는다.
- 대시보드 분류별 거래 창의 목록·로딩 영역은 행간만 `--line-height-body`를 쓰고, 창의 나머지는 기존 행간 비율을 유지한다.
- 기존 간격 토큰·컨트롤 높이는 유지한다. 정보 줄이 늘어난 만큼 행 높이는 내용에 따라 늘어난다.
- 수입 금액은 모바일 카드와 넓은 화면의 표 모두 기존 `--amount-income`의 빨간색으로 표시한다. 부호와 금액 가림은 유지한다.
- 넓은 화면의 표 열 구성·정렬·선택·금액 가림·거래 편집 동작은 유지한다.

## 앱 공통 글자 체계

좁은 화면과 넓은 화면에 같은 글자 토큰을 쓴다. px 값의 원본은
`apps/web/src/styles/tokens.css`이며, 이 문서에 값을 복제하지 않는다.

| 역할 | 토큰 |
|---|---|
| 하단 탭·달력 요일·배지 | `--text-xs` |
| 보조 설명·라벨·메타·태그 | `--text-sub` |
| 본문·표·목록·선택 항목·섹션 제목(h3) | `--text-body` |
| 버튼을 명시적으로 지정하는 곳 | `--text-button` |
| 강조 금액·이름·로고 | `--text-emphasis` |
| 카드 제목·창 제목·강조 합계 | `--text-title` |
| 페이지 제목 | `--text-page-title` |
| 터치 입력칸 | `--text-input` |
| 본문 행간 | `--line-height-body` |

화면·창 단위로 글자·행간 토큰을 재정의하지 않는다. `designTokens.test.ts`가
`tokens.css` 밖의 `--text-*`·`--line-height-*` 선언과 원본에 없는 토큰 참조를 막는다.
차트 내부 글자와 기존 행간 비율은 각 부품의 규칙을 유지한다.

## 토큰과 공용 부품

- 색·간격·글자·모서리·컨트롤 높이는 기존 디자인 토큰을 우선한다. 이 문서에 토큰 값을 복제하지 않는다.
- 스타일은 CSS Modules, 아이콘은 `common/Icon.tsx`의 기존 체계를 따른다.
- `PageHeader`, `TextField`, `Switch`, `ConfirmDialog` 등 `apps/web/src/common/`의 부품을 먼저 확인한다.
- 라벨 옆 별도 도움말처럼 공용 부품만으로 구성하기 어려운 경우, 기존 React Aria 부품과
  공용 스타일로 조합하고 라벨 연결·포커스·오류 처리를 유지한다.
- 화면별 요구를 해결하려고 공용 부품의 기본 동작을 임의로 바꾸지 않는다.
  여러 화면에서 같은 구성이 필요해질 때 실제 사용처를 확인해 공용화한다.
- 터치 영역·주 버튼 높이·선택 조각·그림자는 `--touch-target`, `--control-height-primary`, `--segment-height`, `--tab-height`, `--shadow-raised`를 쓴다.
- `apps/web/src/styles/designTokens.test.ts`가 `tokens.css` 밖의 CSS에서 색 리터럴, 숫자 `font-size`, `44px`/`48px` 리터럴을 막는다.
  `44px`은 모든 곳에서, `48px`은 `height`·`min-height`·`max-height`에서만 막는다(열 너비는 허용). 예외가 필요하면 토큰을 먼저 추가한다.

## 적용과 검증

글자 크기·컨트롤 높이 토큰과 문구 어미는 앱 전체에 적용한다. `designTokens.test.ts`는
CSS의 색·글자 크기 리터럴, `44px` 리터럴과 `48px` 높이, `tokens.css` 밖의 글자·행간 토큰
선언과 정의되지 않은 참조를 막고, `copyTone.test.ts`는 웹 앱 문구의 합니다체 어미를 막는다
(서버 문구는 검사하지 않는다).

배치·도움말 등 나머지 규칙은 앱 전체가 충족한다고 확인하지 않았다. 새 UI와 수정하는
영역부터 적용한다. 화면별 의미·권한·데이터 처리 동작은 통일만을 위해 바꾸지 않는다.
도움말은 공용 부품 `apps/web/src/common/HelpButton.tsx`를 쓴다(그룹 관리·소득공제).

화면 값(크기·높이·색·간격·글자)을 바꾸려면 구현을 확정하기 전에 근거와 바뀌는 화면의
전·후를 보여 사용자 승인을 받는다. 스타일 통합·리팩터링의 부수 효과로 값이 달라지는
경우도 같다. 승인된 값을 그대로 적용하는 수정은 다시 묻지 않는다.

검토 시 다음을 확인한다.

1. 375px 기준 이전·이후 화면에서 우측 조작부와 좌측 정보가 구분되는가.
2. 공통 글자·높이·간격에 영향을 주는 변경은 바뀐 화면뿐 아니라 여러 화면의 같은 역할
   (페이지 제목·카드 제목·본문·보조·버튼·컨트롤 높이)의 실제 계산값을 375px과 1280px에서 비교했는가.
3. 320px·데스크톱·긴 이름·글자 확대에서도 겹침과 의도하지 않은 가로 스크롤이 없는가.
4. 도움말의 터치·재누르기·바깥 터치·Esc·포커스 복귀와 설정값 불변이 확인되는가.
5. 관리자·일반 멤버, 빈 상태·로딩·오류·비활성·저장 중에도 정보와 조작이 유지되는가.
6. 웹 코드 변경은 [개발 문서](development.md)의 최종 검증을 통과했는가.
7. 브라우저 검증과 설치형 PWA 실기기 검증을 구분해 보고했는가.
   iOS·Android의 실제 터치·키보드·안전 영역은 실기기로 확인한다.
