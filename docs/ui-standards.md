# UI 표준

Salad Bowl의 새 화면과 UI 수정에 적용하는 공통 기준이다.
2026-11-13 그룹 관리 개선에서 합의한 배치·문구·도움말 원칙을 정리했다.

**정보는 왼쪽, 조작은 오른쪽에 두고, 기본 화면에는 판단에 필요한 내용만 보여준다.**
모바일 PWA에서 터치로 사용할 수 있어야 하며, 넓은 화면에서도 같은 배치 원칙을 따른다.

## 기존 지침과 적용 범위

| 근거 | 역할 |
|---|---|
| [에이전트 공통 규칙](agent-guidelines.md) | 토큰·공용 부품 우선, 접근성·데이터 보존, 검증 절차 |
| [초기 웹 화면 설계](superpowers/specs/2026-10-19-web-screen-design.md) | 초기 PC 설계와 아이콘·CSS Modules 선택의 이력 |
| [React Aria 도입 설계](superpowers/specs/2026-10-22-react-aria-rollout-design.md) | 공용 입력·오버레이·접근성의 설계 이력 |
| [화면 일관성 설계](superpowers/specs/2026-10-30-design-consistency-design.md) | 제목·추가 버튼·금액 표기의 설계 이력 |
| [iOS PWA 외형](ios-pwa-appearance.md) | 상태 바 배경과 실기기 검증의 한계 |

과거 설계의 당시 화면·수치가 현재 구현을 뜻하지는 않는다. 공통 UI 방향은 이 문서,
색·크기 등의 실제 값은 `apps/web/src/styles/tokens.css`, 동작은 현재 공용 부품과
해당 기능의 설계를 함께 확인한다. 기준을 바꾸면 이 문서도 함께 갱신한다.

## 배치

| 요소 | 기준 | 예시 |
|---|---|---|
| 화면·섹션 제목과 실행 버튼 | 제목은 좌측, 해당 버튼은 같은 영역의 우측 끝 | 내 그룹 / 추가, 초대 링크 / 초대 링크 만들기 |
| 입력과 실행 버튼 | 입력 영역은 좌측에서 남는 폭을 사용하고, 버튼은 우측 | 새 이름 입력 / 이름 바꾸기, 초대 주소 / 링크 복사 |
| 설정 행 | 제목·설명은 좌측, 토글 등 설정형 입력은 우측 | 내 거래 그룹 공개 / 토글 |
| 목록 행 | 이름·상태는 좌측에 쌓고, 행별 버튼은 우측 | 멤버 정보 / 내보내기, 차단 정보 / 차단 해제 |
| 독립 실행 버튼 | 소속 섹션의 우측 끝 | 그룹 나가기, 만들기 |
| 확인창의 버튼 묶음 | 확인·실행을 우측, 취소를 그 왼쪽 | 취소 / 나가기 확인 |

- 우측은 화면 전체가 아닌 **그 조작이 속한 카드·섹션·행의 오른쪽 끝**이다.
- 도움말 `?`는 대상 제목 옆에 둔다. 실행 버튼과 구별하고, 토글을 누르는 영역에 넣지 않는다.
- 일반 폼 입력 전체를 우측으로 몰지 않는다. 좌측 입력과 우측 실행 버튼의 관계를 유지한다.
- 긴 이름·설명은 좌측에서 줄바꿈한다. 우측 버튼·토글을 화면 밖으로 밀거나 서로 겹치게 하지 않는다.
- 공간이 부족해 실행 버튼을 다음 줄에 놓아야 해도 우측 정렬을 유지한다.
- 내비게이션·탭·차트 등은 각 공용 부품의 구조를 따른다. 이 정렬 규칙은 제목·설정·폼·목록의 조작에 적용한다.

```text
제목 (?)                         [실행]

입력 라벨
[입력 영역                    ] [저장]

설정 제목 (?)                    [토글]
짧은 설명

멤버 이름                     [내보내기]
역할 · 공개 상태 · 합류 일시
```

## 문구와 정보의 우선순위

- 제목은 기능을 식별할 수 있게 짧게 쓴다. 버튼은 누르면 일어나는 행동을 쓴다.
- 기본 설명은 가능하면 짧은 한 문장으로 쓴다. 폭이 좁다는 이유로 필요한 내용을 잘라 숨기지는 않는다.
- 제목·버튼만으로 이해되는 동작에는 설명을 덧붙이지 않는다.
- 보충 규칙·배경·상세 절차는 도움말로 옮긴다.
- 현재 상태·실행 불가 이유·오류와 해결 방법은 화면에 직접 표시한다.
- 나가기·내보내기·삭제의 결과는 확인창에 명시한다. 중요한 결과를 도움말에만 넣지 않는다.

| 사례 | 기본 화면 | 도움말 또는 확인창 |
|---|---|---|
| 내 거래 그룹 공개 | 이 그룹에 내 거래를 공유해요. | 끄면 그룹 대시보드·그룹 거래에서 제외됨, 숨긴 거래는 공개해도 보이지 않음 |
| 초대 링크 | 생성·복사 버튼, 생성 후 실제 만료일 | 7일간 유효, 로그인·가입 후 합류 |
| 차단 목록 | 목록 또는 차단한 사람이 없습니다. | 차단 중에는 재합류 불가, 해제 후 재초대 가능 |
| 그룹 정원 초과 | 정원과 새로 초대할 수 없는 이유 | 기본 화면에서 안내 |
| 복사·저장 실패 | 오류와 재시도·직접 복사 등 다음 행동 | 기본 화면에서 안내 |
| 멤버 내보내기 | 내보내기 버튼 | 확인창에 차단과 재합류 제한 명시 |

## 도움말

- PWA에서는 마우스 호버나 HTML `title`에만 의존하지 않는다. `?`를 눌러 여는 팝오버를 쓴다.
- 다시 누르기·바깥 터치·닫기 버튼·Esc로 닫을 수 있게 한다.
- 키보드로 열고 읽고 닫을 수 있어야 한다. 닫을 때 포커스가 사라지지 않도록 복귀를 확인한다.
- 버튼과 도움말에는 `내 거래 그룹 공개 도움말`처럼 대상을 구별할 수 있는 접근성 이름을 붙인다.
- 도움말을 열거나 닫아도 토글 값이 바뀌거나 저장 요청이 발생하지 않아야 한다.
- 팝오버는 화면 안에서 줄바꿈하고, 높이가 부족하면 내부에서 스크롤할 수 있게 한다.
- 짧은 보충 설명은 팝오버로 제공한다. 입력·선택·확인이 필요한 흐름은 기존 대화상자·시트를 쓴다.

## PWA와 접근성

- 좁은 화면 기준은 기존 `(max-width: 820px)`와 `common/useMediaQuery.ts`를 따른다.
- 모바일 버튼·아이콘 버튼·도움말·토글의 누르는 영역은 최소 44×44px로 확보한다.
  아이콘이나 토글 그림 자체를 44px로 키울 필요는 없다.
- 기존 `AppLayout`의 상하좌우 안전 영역과 하단 탭 바 여백을 유지한다.
  팝오버와 확인창이 화면 밖으로 나가거나 조작부를 가리지 않게 확인한다.
- 긴 그룹명·멤버명, 글자 확대 시 줄바꿈과 행간을 확인한다. 고정 높이로 내용이 잘리지 않게 한다.
- 입력과 토글은 보이는 라벨과 연결한다. 아이콘은 장식으로 처리하고 버튼 이름을 별도로 제공한다.
- 포커스·선택·비활성·저장 중·오류 상태를 유지한다. 저장 중 중복 실행을 막고 실패 시 재시도할 수 있게 한다.
- 즉시 반영되는 설정은 Switch, 저장 시 반영되는 선택은 Checkbox를 쓰는 기존 구분을 따른다.

## 대화상자·시트·선택 팝오버

그룹 생성·내보내기 확인·업로드·거래 편집·공통 설정 등은 같은 글자 체계를 쓴다.
넓은 화면의 모달과 모바일 시트 모두 적용하며, 선택 팝오버의 항목도 본문 크기를 따른다.

| 역할 | 크기 | 토큰 |
|---|---|---|
| 창 제목 | 16px | `--text-xl` |
| 본문·섹션 제목·선택 항목 | 15px | `--text-lg` |
| 버튼 | 14px | `--text-card-action` |
| 입력 라벨·보조 설명 | 13px | `--text-md` |

- `Overlay.module.css`의 공용 `typography`를 `DialogFrame`, `BottomSheet`, `ResponsiveOverlay`에서 사용한다.
- 기본 행간은 1.5로 두고 창 본문과 폼의 간격도 함께 확보한다.
- 모바일 입력칸의 16px 글자와 44px 터치 영역, 기존 안전 영역·스크롤·포커스·닫기 동작을 유지한다.
- 창 안의 본문이 길면 스크롤할 수 있게 한다. 화면 전체의 기본 글자 크기는 바꾸지 않는다.
- 그룹 카드와 공통 창의 버튼은 같은 14px 토큰을 재사용한다.

## 토큰과 공용 부품

- 색·간격·글자·모서리·컨트롤 높이는 기존 디자인 토큰을 우선한다. 이 문서에 토큰 값을 복제하지 않는다.
- 스타일은 CSS Modules, 아이콘은 `common/Icon.tsx`의 기존 체계를 따른다.
- `PageHeader`, `TextField`, `Switch`, `ConfirmDialog` 등 `apps/web/src/common/`의 부품을 먼저 확인한다.
- 라벨 옆 별도 도움말처럼 공용 부품만으로 구성하기 어려운 경우, 기존 React Aria 부품과
  공용 스타일로 조합하고 라벨 연결·포커스·오류 처리를 유지한다.
- 화면별 요구를 해결하려고 공용 부품의 기본 동작을 임의로 바꾸지 않는다.
  여러 화면에서 같은 구성이 필요해질 때 실제 사용처를 확인해 공용화한다.

## 적용과 검증

그룹 관리에 먼저 적용했다. 이름 변경·초대 생성·복사·나가기의 우측 정렬,
좌측 설명·우측 공개 토글, 세 종류의 도움말이 기준 사례다.
현재 도움말 구현은 `apps/web/src/groups/GroupHelp.tsx`이며 아직 공용 부품은 아니다.

다른 화면이 모두 이 표준을 충족한다고 보지는 않는다. 새 UI와 수정하는 영역부터 적용하고,
화면별 의미나 권한·데이터 처리 동작을 배치 통일만을 위해 바꾸지 않는다.

검토 시 다음을 확인한다.

1. 375px 기준 이전·이후 화면에서 우측 조작부와 좌측 정보가 구분되는가.
2. 320px·데스크톱·긴 이름·글자 확대에서도 겹침과 의도하지 않은 가로 스크롤이 없는가.
3. 도움말의 터치·재누르기·바깥 터치·Esc·포커스 복귀와 설정값 불변이 확인되는가.
4. 관리자·일반 멤버, 빈 상태·로딩·오류·비활성·저장 중에도 정보와 조작이 유지되는가.
5. 웹 코드 변경은 [개발 문서](development.md)의 최종 검증을 통과했는가.
6. 브라우저 검증과 설치형 PWA 실기기 검증을 구분해 보고했는가.
   iOS·Android의 실제 터치·키보드·안전 영역은 실기기로 확인한다.
