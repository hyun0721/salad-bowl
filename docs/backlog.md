# 잔여 작업 (Backlog)

나중에 진행하기로 한 작업이다. 계획(Plan)에 들어가면 해당 계획 문서로 옮기고 여기서 지운다.

## 기능
- **대용량 엑셀 업로드(스트리밍 파싱)**: 지금은 한 번에 최대 3개월치·512KB로 제한한다(Plan 05). 1년치 같은 큰 파일을 받으려면 `가계부 내역` 시트만 행 단위로 읽는 스트리밍 파서(예: `excel-streaming-reader`, POI 5.5.x 필요)로 바꾸고, `memoryTest`의 상한 파일 크기를 함께 올린다. 파싱 메모리는 XSSF 기준 xlsx 1MB당 약 170MB다.
- **그룹 관리자 위임**: 지금 관리자는 그룹을 나갈 수도, 다른 멤버에게 관리자를 넘길 수도 없다(API `ADMIN_CANNOT_LEAVE`). 관리자 넘기기와, 넘긴 뒤 나가기를 만든다. 그룹 삭제도 함께 검토한다.
- **거래 목록 낮은 화면**: 좁은 화면 거래 목록은 창 높이에 맞추고 본문을 스크롤하지 않는다(Plan 17). 가로 모드 폰처럼 높이가 낮으면 목록이 한두 행만 남고, 더 낮으면 풋터가 잘린다. 높이가 낮을 때(`max-height` 미디어 쿼리 등) 페이지 스크롤로 돌아가는 규칙을 검토한다. 같은 화면의 카드 수정됨 배지 앞 간격이 `gap`과 배지 `margin-left`로 겹치는 것도 함께 정리한다. 넓은 화면 가로 모드(노치)에서는 목록 왼쪽과 목록·패널 사이에도 안전 영역 여백이 들어가 빈 칸이 생기므로, 화면 끝에 닿는 쪽에만 inset을 두도록 정리한다.

- **태그 기간 검색·금액 합계**: 지금 태그 검색은 선택한 달 안에서만 한다(메모 태그 PR). `from`/`to`로 넓히고 태그별 금액 합계를 낼 때는 `GET /groups/{id}/tags`와 같은 범위(공개 중인 멤버의 숨기지 않은 거래)를 정확 일치로 더한다. 거래 하나에 태그가 둘이면 양쪽에 들어가므로 태그 합계를 다시 더해 전체 합계처럼 보이면 안 된다. 그룹 4.8만 건 기준 태그 목록은 정규식으로 약 47ms였다(로컬 측정). 눈에 띄게 느려지면 `memo_tags text[]` 컬럼과 GIN 인덱스를 둔다.

## 인프라
