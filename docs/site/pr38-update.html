PR #38 · 새 버전 확인과 적용의 최종 구조

Long image

A

Answer

앱은 새 버전을 확인해 알림을 띄우고, 사용자가 새로고침을 누르면 서비스워커 상태에 맞춰 화면을 다시 불러옵니다. PR #38은 이 마지막 적용 단계를 보완합니다.

  1. 확인: 서비스워커 등록 후 1시간마다, 화면으로 돌아올 때 업데이트를 조회합니다.
  2. 표시: 플러그인의 needRefresh가 켜지면 새 버전 알림을 보여줍니다.
  3. 적용: 대기 워커가 없으면 즉시, 있으면 활성화된 뒤 새로고침합니다.

1

새 버전은 어떻게 확인하고 알려주나요?

Diagram structure
  • useAppUpdate hook
  • 서비스워커 등록 객체 sw
  • PWA 플러그인 plugin
  • UpdatePrompt ui
  • hook → sw · 1시간 경과 또는 화면 복귀: update()
  • plugin → hook · 새 버전 감지 상태: needRefresh
  • hook → ui · needRefresh가 true면 알림 표시
  • ui → hook · 새로고침: update / 나중에: dismiss

registration.update()는 새 서비스워커를 확인하는 호출입니다. 화면을 다시 불러오는 window.location.reload()와 역할이 다릅니다. 확인이 실패하면 오류를 무시하고 다음 확인 기회를 기다립니다.1

이 흐름은 앱의 명시적 재확인 경로입니다. 등록·설치 상태에 따른 감지는 PWA 플러그인이 담당합니다.1

2

새로고침을 누르면 어떤 경로로 적용되나요?

Diagram structure
  • 새로고침 클릭 click
  • 대기 워커 있음? check
  • 활성화 감시 등록 listen
  • 활성화 요청 activate
  • activated 감지 ready
  • 화면 새로고침 reload
  • activate → ready · 상태 변경
  • check → listen · 있음
  • check → reload · 없음
  • click → check · update()
  • listen → activate · 감시 후
  • ready → reload · 활성화 완료
  1. 대기 워커 있음? ↗

    저장해 둔 registrationRef에서 waiting을 읽습니다.

  2. 활성화 감시 등록 ↗

    대기 워커에 statechange 리스너를 먼저 붙입니다.

  3. 활성화 요청 ↗

    updateServiceWorker(true)로 대기 워커의 활성화를 요청합니다.

  4. 화면 새로고침 ↗

    대기 워커가 없으면 즉시, 있으면 activated 상태를 확인한 뒤 reload합니다.

서비스워커는 앱 파일을 관리하는 브라우저의 백그라운드 구성요소입니다. 여기서 대기 워커는 설치를 마치고 활성화를 기다리는 새 서비스워커를 뜻합니다.2

각 구성요소는 무엇을 담당하나요?

구성요소최종 역할PR #38에서 바뀐 부분
Vite PWA 설정registerType: 'prompt', injectRegister: false로 앱 알림 방식 사용기존 설정 유지
useAppUpdate의 등록 콜백1시간 타이머와 화면 복귀 시 확인 설정등록 객체를 registrationRef에 보관
useAppUpdate의 update사용자가 선택한 새 버전을 화면에 적용waiting 유무에 따른 분기와 activated 감시 추가
UpdatePrompt“새 버전이 있어요”, “나중에”, “새로고침” 표시화면 코드 유지, 클릭 동작 테스트 수정
useAppUpdate 테스트확인 주기와 적용 경로 검증즉시 새로고침·활성화 후 새로고침 테스트 추가

확인 주기와 알림 UI는 기존 구조이며, PR #38의 제품 코드 수정은 useAppUpdate.ts에 집중됩니다. 나머지 변경 파일 2개는 테스트입니다.2

사용자는 어떤 결과를 보게 되나요?

상황최종 동작
새 버전 알림이 없음UpdatePrompt가 아무것도 표시하지 않음
알림에서 “나중에” 선택needRefresh를 false로 바꿔 현재 알림을 숨김
“새로고침” 선택, waiting 없음바로 화면 새로고침
“새로고침” 선택, waiting 있음활성화 요청 후 해당 워커의 activated 상태에서 화면 새로고침
업데이트 확인 중 네트워크 실패오류를 무시하고 다음 주기 또는 화면 복귀 때 다시 확인

위 동작은 최종 코드1와 알림 컴포넌트3를 기준으로 정리했습니다. “나중에”는 확인 주기를 끄거나 영구적으로 알림을 차단하는 설정이 아닙니다.
