이 페이지에서서비스와 책임요청 한 건의 경로기능을 바꿀 때 찾을 코드데이터와 브라우저의 경계코드·설정·문서의 배포

서비스와 책임

앱과 문서 사이트는 서로 다른 호스팅을 사용합니다. 웹앱의 주소는 Cloudflare의 pages.dev, 이 가이드의 주소는 GitHub의 github.io입니다.

구성역할문제가 나면 볼 곳
Cloudflare PagesReact 빌드 파일을 제공하고 /api/*를 Function으로 전달웹 빌드 결과, Functions, _routes.json
RenderSpring Boot API와 인증·권한·거래 처리를 실행배포 커밋, Events·Logs, health
Supabase Postgres사용자·그룹·거래를 저장. API가 JDBC 세션 풀러로 연결DB 연결 설정, Flyway, SQL
GitHub Pagesdocs/site/의 정적 개발 문서 제공Actions의 docs-pages 실행

Supabase의 Auth·Data API는 이 앱의 인증이나 데이터 조회에 사용하지 않습니다. 로그인과 권한 판정은 Spring Boot가 담당합니다.

요청 한 건의 경로

  1. 브라우저가 Cloudflare에서 웹앱을 받습니다.
  2. 웹의 API 클라이언트가 같은 출처의 /api/...를 호출합니다.
  3. Pages Function이 /api 접두어를 제거하고 API_ORIGIN의 Render API로 전달합니다.
  4. API가 프록시 비밀값, 사용자 토큰, 기능별 권한을 확인하고 DB를 조회합니다.
  5. 응답과 쿠키가 프록시를 거쳐 브라우저로 돌아옵니다.

운영 브라우저는 Render를 직접 호출하지 않습니다. /api를 제거하는 곳은 프록시이며, 서버 컨트롤러의 경로에 다시 /api를 붙이지 않습니다.

로컬에서는 Vite의 개발 프록시가 같은 접두어 제거를 수행합니다. DB는 Docker의 Postgres, API는 기본 8080, 웹은 5173 포트를 사용합니다.

웹 경로는 apps/web/, 서버 패키지는 apps/api/src/main/java/com/saladbowl/ 기준입니다. 현재 홈은 지난달 등록 상태와 요약을 보여주고, 월별 등록 현황은 업로드 화면에 있습니다.

데이터와 브라우저의 경계

DB 스키마는 API 시작 시 Flyway가 적용합니다. db/migration/V*.sql의 이미 적용된 파일을 수정하지 말고 새 버전을 추가합니다. 앱을 이전 버전으로 배포해도 DB 스키마는 자동으로 돌아가지 않습니다.

JWT access 토큰은 웹 메모리에, refresh 토큰은 HttpOnly 쿠키에 둡니다. 로그인 여부와 거래 접근 권한은 서버에서 확인합니다. 그룹 화면에 보인다고 소유권이 이동하는 것은 아닙니다.

PWA는 설치와 앱 셸 precache를 지원합니다. API 데이터의 오프라인 사용은 지원하지 않으며, 새 버전 적용은 사용자의 새로고침 선택을 따릅니다. 상세 흐름은 버전 관리와 업데이트에서 확인할 수 있습니다.

코드·설정·문서의 배포

웹은 Cloudflare의 Git 연동, API는 Render의 Git 연동으로 배포됩니다. GitHub Actions는 검사와 설정값 동기화를 담당하며, 문서만 docs-pages가 직접 배포합니다.

운영 설정의 원본은 GitHub Environment production입니다. 문서 배포 환경 github-pages와 구분하세요. 설정 변경과 실제 적용은 배포·운영 가이드를 따릅니다.
