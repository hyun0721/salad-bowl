# Task 리뷰

Claude와 Codex 모두 사용할 수 있는 저장소 내부 리뷰 절차다.
외부 플러그인 캐시의 절대 경로를 전제로 하지 않는다.

## 입력

- BRIEF_FILE: 요구사항과 변경 범위
- REPORT_FILE: 구현자의 변경·검증 보고
- BASE_SHA / HEAD_SHA: 리뷰할 커밋 범위
- DIFF_FILE: 커밋 목록·통계·문맥을 포함한 diff
- GLOBAL_CONSTRAINTS: 관련 설계·계획의 공통 제약 또는 그 파일 경로

입력이 없으면 사용자 요청과 사용 가능한 diff를 기준으로 하고, 확인하지 못한
범위를 보고한다. 존재하지 않는 보고서나 검증 결과를 가정하지 않는다.

## 방법

1. brief·공통 제약·구현자 보고를 읽고 diff와 대조한다. 보고는 검증되지 않은 주장이다.
2. 요구사항 누락·범위 밖 변경·잘못 이해한 동작을 확인한다.
3. 코드 품질·예외 처리·경계 조건·동작을 확인하는 테스트를 점검한다.
   diff 밖 탐색은 구체적인 위험을 확인하는 범위로 좁힌다.
4. 기존 검증 결과를 이유 없이 재실행하지 않는다. 코드에서 구체적인 의문이
   생겼으면 해당 의문을 확인하는 검증만 추가하고 이유를 기록한다.
5. 읽기 전용 리뷰에서는 코드·인덱스·브랜치를 변경하지 않는다.

## 보고

- 요구사항 충족 판정과 코드 품질 판정을 구분한다.
- 발견별 심각도(Critical / Important / Minor), 파일과 위치, 재현 또는 근거,
  영향, 필요한 수정 방향을 적는다.
- 경고는 원인과 영향으로 판단한다. 경고라는 이유만으로 오류나 차단 사유로 분류하지 않는다.
- 변경 밖이라 확인할 수 없는 요구사항, 실행하지 못한 검증, 추측을 명시한다.
- 발견이 없으면 없다고 적고 실제 검토 범위와 남은 검증 한계를 보고한다.
